*** Modularity

If this is your main local configuration and you don't want to deviate
from it, it's more sustainable in the long run to have =~/.emacs.d= as a
directory contains links to some =*.el= files you want. This has the
benefit of keeping the =.gitignore= and the git repository clean, and
the file =straight/versions/default.el= can be versioned normally
without =git add --force= when you remember it. It makes a new install
more stable and draw a balanced line between local state and
transferable configuration.

*** Rely on ~use-package~ to install and load packages

Emacs ships =use-package= since 29.1, and =which-key= and =editorconfig=
since 30.1.  Where Emacs ships them, straight.el treats them as
built-in, so no build of its own shadows them; nothing requires a
newer version.  A library found right after straight.el starts, before
it activates any build, is one Emacs or the system ships.  Without
them, as on an older Emacs, straight.el builds them; =use-package=
then comes from the full git coordinates below, as =package.el= is
disabled.

Other packages Emacs ships are still built by straight.el, because
packages require newer versions than older Emacs releases ship:
=transient= (0.13 for magit and forge), =seq= (2.24 for magit, cider,
flycheck and pet), =eldoc= (1.11 for lsp-mode), =project= (0.9.8 for
breadcrumb, with =xref= for =project=) and =jsonrpc= (1.0.25 for dape).
straight.el compares no versions, so it cannot tell when the shipped
one is recent enough.

#+BEGIN_SRC elisp
(dolist (package '(use-package which-key editorconfig))
  (when (locate-library (symbol-name package))
    (add-to-list 'straight-built-in-pseudo-packages package)))

(straight-use-package
 (if (memq 'use-package straight-built-in-pseudo-packages)
     'use-package
   '(use-package
      :type git
      :host github
      :repo "emacs-straight/use-package"
      :branch "master")))

(setq straight-use-package-by-default t)
(setq use-package-always-defer t)
#+END_SRC

According to [[https://github.com/jwiegley/use-package][the documentation]]:
- ~:init~ executes code before a package is loaded;
- ~:config~ executes code after a package was loaded;
- ~:custom~ defines custom variables for this package.

*** Safe package update

=C-c P u= updates every package, and keeps the update only when the
configuration still passes its fast tests:
1. refuse to start when =tests/run= under =user-emacs-directory= is
   missing or not executable, before anything changes;
2. pull every package with ~straight-pull-all~, then rebuild the
   changed ones with ~straight-check-all~;
3. run =tests/run fast= in the buffer =*Package update tests*=, while
   Emacs stays usable;
4. on success, write the new versions to the lockfile with
   ~straight-freeze-versions~; otherwise restore the lockfile versions
   with ~straight-thaw-versions~ and rebuild.

Every outcome but success restores the lockfile versions: a fetch or
merge that failed for some repositories, an error or =C-g= during the
pull or the rebuild, a test run that could not start, and a test run
that failed.  The restore names the repositories it could not check
out.  straight.el asks what to do about a repository it cannot pull or
check out; the command never discards local changes itself.  A second
=C-c P u= is refused while the tests of the first one run.  The freeze
or thaw runs from the process sentinel once the tests end: it blocks
Emacs, and Emacs inhibits =C-g= there, which is deliberate, since a
thaw stopped half way leaves the tree inconsistent.  macOS has no
private X display for the test frames, so there the tests run with
=EMACS_TEST_GUI=0=.

The fast tests include the golden tests,
=tests/scenarios/l1-golden-gui.el=: for each fixture of
=tests/golden/=, the face of every token and the result of
=indent-region= are recorded.  An update that changes them fails, and
the test buffer names the first line that differs.  To keep an
intended change, pull with =M-x straight-pull-all= and rebuild with
=M-x straight-check-all= (the test sessions load the built packages
and never rebuild them), approve the new records with
=UPDATE_GOLDEN=1 tests/run fast golden=, review and commit
=tests/golden/=, then press =C-c P u= again.  To abandon the update
instead, run =M-x straight-thaw-versions=, then =M-x
straight-check-all=.  They need a graphical frame, so macOS skips
them.

~C-c P~ is a prefix reserved for package-management commands, shown by
which-key.

#+BEGIN_SRC elisp
(defvar my/straight-safe-update-boundaries
  ;; `straight-pull-all' returns only the merge failures.
  (list :pull (lambda () (delete-dups (append (straight-fetch-all) (straight-merge-all))))
        :rebuild #'straight-check-all
        :test (lambda (runner done)
                ;; Run RUNNER fast asynchronously; call DONE with its exit
                ;; status.  Signal when it cannot start.
                (let ((default-directory user-emacs-directory)
                      (process-environment
                       (if my/macos-p
                           (cons "EMACS_TEST_GUI=0" process-environment)
                         process-environment))
                      (buffer (get-buffer-create "*Package update tests*")))
                  (with-current-buffer buffer (erase-buffer))
                  (display-buffer buffer)
                  (make-process
                   :name "package-update-tests"
                   :buffer buffer
                   :command (list runner "fast")
                   :sentinel (lambda (process _event)
                               (unless (process-live-p process)
                                 (funcall done (process-exit-status process)))))))
        :freeze #'straight-freeze-versions
        :thaw #'straight-thaw-versions)
  "The effects of `my/straight-safe-update', as a plist of functions.
:pull pulls every package and returns the recipes it could not pull;
:rebuild rebuilds the changed packages; :test takes the test runner
and a function it calls with the exit status of `RUNNER fast'; :freeze
writes the lockfile; :thaw checks out the lockfile versions and returns
the recipes it could not check out.")

(defun my/straight-safe-update ()
  "Update every package, keeping the update only if the fast tests pass.
Pull every package and rebuild the changed ones, then run `tests/run
fast'.  When the tests pass, write the new versions to the lockfile;
when a pull fails, the pull or rebuild signals or is quit, or the tests
fail or cannot start, restore the lockfile versions and rebuild."
  (interactive)
  (let* ((effect (lambda (key &rest arguments)
                   (apply (plist-get my/straight-safe-update-boundaries key) arguments)))
         (packages (lambda (recipes)
                     (mapconcat (lambda (recipe) (plist-get recipe :package)) recipes ", ")))
         (runner (expand-file-name "tests/run" user-emacs-directory))
         (restore (lambda (reason)
                    (let ((unthawed (funcall effect :thaw)))
                      (funcall effect :rebuild)
                      (if unthawed
                          (message "Package update undone: %s; %s not checked out, run M-x straight-thaw-versions"
                                   reason (funcall packages unthawed))
                        (message "Package update undone: %s; the lockfile versions are back"
                                 reason))))))
    (unless (file-executable-p runner)
      (user-error "Package update not started: %s is not an executable file" runner))
    (when (process-live-p (get-process "package-update-tests"))
      (user-error "Package update not started: the tests of the previous one still run"))
    (when-let* ((reason
                 (condition-case err
                     (if-let* ((unpulled (funcall effect :pull)))
                         (format "%s not pulled" (funcall packages unpulled))
                       (funcall effect :rebuild)
                       ;; Freeze and thaw run from the sentinel, where Emacs
                       ;; inhibits C-g: a half-done thaw is worse than a wait.
                       (funcall effect :test runner
                                (lambda (status)
                                  (if (not (eql status 0))
                                      (funcall restore (format "the tests failed (exit %s)" status))
                                    (message "Package update: the tests passed, freezing the lockfile")
                                    (funcall effect :freeze))))
                       nil)
                   ((error quit)
                    (format "the update stopped (%s)" (error-message-string err))))))
      (funcall restore reason))))

(keymap-global-set "C-c P u" #'my/straight-safe-update)
#+END_SRC

** Start-up performance benchmarking
:PROPERTIES:
:CUSTOM_ID: startup_benchmark
:END:

=benchmark-init= wraps every =require= call with timing advice so each
load is individually measured.  That instrumentation itself costs time
— enough to inflate startup noticeably when running normally.  The
package is therefore only activated when the =EMACS_PROFILE= env var is
set, and is completely absent from =features= during a normal launch:
no load cost, no per-call overhead.

#+BEGIN_SRC elisp
(use-package benchmark-init
  ;; Only activate when explicitly profiling — benchmark-init wraps every
  ;; `require' call with timing advice, which itself adds latency to each
  ;; require during normal startup.  Set the EMACS_PROFILE env variable to
  ;; opt in: EMACS_PROFILE=1 emacs
  :if (getenv "EMACS_PROFILE")
  :demand t
  :init (benchmark-init/activate)
  :hook (after-init . benchmark-init/deactivate))
#+END_SRC

To profile startup, launch with =EMACS_PROFILE=1 emacs= then call
=M-x benchmark-init/show-durations-tree=.

** Increase performance and responsiveness
:PROPERTIES:
:CUSTOM_ID: emacs_performance
:END:

Measure initialization and a usable graphical frame separately. The value
=after-init-time - before-init-time= excludes startup hooks, frame setup,
and later idle work. An =--eval= expression that immediately calls
=kill-emacs= therefore does not measure a usable editor. See the
[[https://www.gnu.org/software/emacs/manual/html_node/elisp/Startup-Summary.html][GNU startup sequence]] and the measurement report of plan 036 (2026-09-06).

*** Reproducible measurements

Run the opt-in harness from a dedicated worktree with the installed
Emacs and its existing packages. It copies mutable editor state and
uses private server sockets and disposable Git projects. As in the
tests, it reads the live packages, builds and native caches read-only:
straight.el safe mode forbids rebuilding them, and git climbs from no
package's subdirectory into its repository. =snapshot.py= copies the
package repositories, about 2.3 GiB, for =run.py --packages=; the
builds still come from the live tree.

#+begin_src bash :tangle no
python3 tests/performance/run.py --output tmp/startup-measured
python3 tests/performance/run.py --minimal --output tmp/startup-minimal
python3 tests/performance/run.py --client --output tmp/client-measured
python3 tests/performance/compare.py --daemon --output tmp/daemon-boots BEFORE AFTER
python3 tests/performance/smoke.py --output tmp/startup-smoke
python3 tests/performance/runtime.py --output tmp/editing --seconds 60
python3 tests/performance/runtime.py --output tmp/soak --seconds 1800
python3 tests/performance/analyze.py tmp/soak/runtime.jsonl --skip-samples 120
python3 tests/performance/workflows.py --output tmp/workflows
python3 tests/performance/first_use.py --output tmp/first-use --idle 3
tests/run.sh
tests/test-integration.sh
#+end_src

=compare.py= alternates the source directories it is given, each
holding an =init.el= and an =early-init.el=, reversing their order
every round; =--daemon= times daemon boots instead of framed starts.
=first_use.py= times the first =C-x g=, =C-x b=, =C-s= and =M-.= in a
client frame, each on a fresh daemon idle for =--idle= seconds, and
checks that each key showed what it opens.

Use a new output directory for every run. Startup defaults to two
warm-up launches followed by 30 measured launches. The first launch
remains in the raw data; it is not called filesystem-cold. The summary
reports the median, nearest-rank p95, maximum and failures. Manifests
record source hashes, commit, package revisions, Emacs binary, backend
and native-cache state. Frame dimensions and visibility are recorded
in every startup sample.

Frames draw on a private Xvfb display, as the test frames do, so no
measurement reaches the user's screen. That display is X11 under GTK,
not the user's Wayland: compare its numbers with each other. Every
script that starts Emacs takes =--user-display= to draw on the
inherited display instead, and needs it without Xvfb or with an Emacs
that cannot draw on X, as on macOS. There, on Linux with a Wayland display, the harness selects
=GDK_BACKEND=wayland= for its private children. =EMACS_PERF_BACKEND=x11=
explicitly tests XWayland. The ambient shell on this machine currently
forces X11, which can also break client-frame creation when the client
passes a Wayland display name. The harness does not modify shell or
system settings. macOS runtime results remain unmeasured.

The readiness command runs after window setup and forces redisplay.
Client measurements include another IPC round trip to inspect and
redisplay the created frame, so they are conservative software
measurements. Neither measures physical input-to-photon latency or
proves equality with Zed.

For attribution, add =--profile= to a startup or runtime command.
Runtime =--profile-delay 15 --seconds 45= separates the later profile
from first use. CPU and allocation profiles can be opened with
=profiler-find-profile=, or summarized with:

#+begin_src bash :tangle no
emacs --batch -Q --load tests/performance/profile-summary.el \
  tmp/editing/runtime.jsonl.cpu.el tmp/editing/runtime.jsonl.memory.el
#+end_src

Repeat acceptance timings with profiling disabled. Additional runtime
options are =--large=, =--long-lines=, =--interval .1= for denser command
sequences, and repeatable =--copy path= for disposable copies of real
files. The probes distinguish first file opening, server
initialization, editing commands plus redisplay, and command-loop gaps
between timer callbacks. A server reporting initialized is not proof
that every external index or possible workflow is ready. The scenario
integrations exercise actual navigation and formatting separately. See
[[https://www.gnu.org/software/emacs/manual/html_node/elisp/Profiling.html][GNU profiling documentation]].

*** Garbage collection policy

Automatic collection requires both the byte threshold and the percentage
of the current heap to be exceeded. Raising the threshold postpones
collection; it does not make allocation free or prevent explicit calls to
=garbage-collect=. Larger heaps can create memory pressure and longer
individual pauses. See [[https://www.gnu.org/software/emacs/manual/html_node/elisp/Garbage-Collection.html][GNU garbage collection documentation]].

The configured runtime threshold is 512 MiB. The MCP security wrapper
temporarily binds it to 1 MB during tool evaluations, then restores it.
Read runtime values through an ordinary private =emacsclient --eval=
session when profiling; an MCP observation inside that wrapper describes
the evaluation, not the editor's normal GC policy. The 32 and 64 MiB
experiments reduced resident memory but increased total GC time without
improving editing p95, so the existing threshold was retained.

*** Optimise garbage collection on startup

#+BEGIN_SRC elisp :tangle ./early-init.el
(defvar my/gc-cons-threshold (* 512 1024 1024) ; in bytes
  "My default desired value of `gc-cons-threshold'
during normal emacs operations.")

;; Automatic GC requires BOTH the byte threshold and the heap percentage
;; to be exceeded. A high startup threshold postpones automatic collection;
;; it cannot prevent a package from calling `garbage-collect' explicitly.
;; Restore a bounded runtime threshold after startup.
(setq gc-cons-threshold most-positive-fixnum
      gc-cons-percentage 1.0)

(defun my/restore-gc-threshold ()
  "Restore the runtime garbage collection thresholds after startup."
  (setq gc-cons-threshold my/gc-cons-threshold
        gc-cons-percentage 0.1))

(add-hook 'emacs-startup-hook #'my/restore-gc-threshold)
#+END_SRC

*** Fast Scroll

Fontification is handled by jit-lock's demand-driven mode with an
input-aware deferral strategy.  The behaviour of =jit-lock-defer-time=
is determined by the C redisplay engine calling =jit-lock-function=
(=jit-lock.el:367=):

- *nil (Emacs default)*: =jit-lock-defer-timer= is never created.
  Every redisplay cycle that encounters unfontified text calls
  =jit-lock-fontify-now= synchronously — fontification is immediate but
  can block input processing in buffers with many jit-lock clients
  (font-lock, pangu-spacing, etc.).

- *0 (our setting)*: a global idle timer is created with delay 0.
  =jit-lock-function= checks =(input-pending-p)=: when no input is
  pending, text is fontified immediately (same as nil); when input IS
  pending, the region is marked =fontified='defer= and the buffer is
  added to =jit-lock-defer-buffers=.  The idle timer fires
  =jit-lock-deferred-fontify=, which resets those regions to
  =fontified=nil= and calls =(redisplay)= so the engine re-fontifies
  them normally.  Result: typing and scrolling are never blocked by
  fontification; text appears briefly unfontified during rapid input,
  then catches up in the very next idle moment.

- *N (positive seconds)*: fontification is always deferred regardless
  of input state.  =jit-lock-deferred-fontify= fires after N seconds
  idle.  This adds a fixed visual lag to every fontification event and
  is generally undesirable.

Stealth fontification pre-fontifies the rest of the buffer during
idle time so that jumping to a previously invisible region is less
likely to cause a visible pause.

Two additional C-level redisplay settings eliminate the stall that
occurs when holding down an arrow key causes the first window scroll.
=fast-but-imprecise-scrolling= tells the display engine to skip
fontification of intermediate screens during rapid scrolling.
=redisplay-skip-fontification-on-input= (Emacs 28+) goes further: when
input is already pending at the start of a command, the
=fontification_functions= hook is not called at all, letting the scroll
catch up before fontifying.

#+begin_src elisp
;; Defer fontification while input is pending (jit-lock-defer-time 0).
;; See the detailed explanation above.  This is the single most
;; effective interactive-latency improvement: it prevents font-lock,
;; pangu-spacing, and other jit-lock clients from blocking keystrokes.
(setq jit-lock-defer-time 0)
;; Stealth-fontify the rest of the buffer during idle time, reducing
;; the chance of a pause when you jump to an unfontified region.
(setq jit-lock-stealth-time 0.2
      jit-lock-stealth-nice 0.1)
;; When scrolling rapidly past unfontified regions, only fontify the
;; portion actually displayed — skip intermediate screens entirely.
(setq fast-but-imprecise-scrolling t)
;; Skip fontification_functions when input is already pending.  This
;; prevents the first window-scroll during held-down arrow keys from
;; blocking: without it, the C redisplay engine calls jit-lock on the
;; entire newly visible region synchronously before reading the next
;; input event.  With it, that fontification is skipped when Emacs is
;; behind on input, letting the scroll catch up first.
(setq redisplay-skip-fontification-on-input t)
;; Auto vertical scroll computes margins on every scroll event — disable it.
(setq auto-window-vscroll nil)
#+end_src

** Org task system

A small Org task layer over explicit =todo.org= files.  Each
participating repository owns its commitments; notes, transcripts,
READMEs, and archives stay outside the agenda.
The personal file still contains its journal, but only headings with a
task keyword enter task views.

For a workflow guide aimed at users (cheatsheet and daily routines),
see [[file:docs/how-to/org-tasks.org][Working with Org tasks]].  This section
is the elisp source plus implementation notes; the user-facing how-to
lives in that companion doc.

*** Agenda sources and display names

The source list is explicit: =my/gtd-file= first, then
=my/org-agenda-source-files=.  Missing files are ignored so the same
configuration works on machines that do not check out every project.
Repository names provide source labels; aliases exist only where the
raw repository name is a poor label.

=org-agenda-files= is computed from that list once init has finished,
from =after-init-hook=: =local.el= loads at the end of =init.el=, so the
values it sets reach the agenda, refiling and the task dashboard.

#+BEGIN_SRC elisp
(require 'seq)

(defcustom my/gtd-file (expand-file-name "~/org/todo.org")
  "Path to the personal task and journal file."
  :type 'file
  :group 'my)

(defcustom my/org-agenda-source-files
  (list (expand-file-name "todo.org" user-emacs-directory))
  "Canonical Org task files after `my/gtd-file', in portfolio display order.
The default is this configuration's own task file; `local.el' lists
the repositories of the machine."
  :type '(repeat file)
  :group 'my)

(defcustom my/org-source-label-alist
  '(("org" . "Personal")
    (".emacs.d" . "Emacs"))
  "Optional display aliases keyed by repository directory name."
  :type '(alist :key-type string :value-type string)
  :group 'my)

(defun my/org-set-agenda-files ()
  "Set `org-agenda-files' to the existing canonical task files.
They are `my/gtd-file', then `my/org-agenda-source-files', as
absolute paths."
  (setq org-agenda-files
        (seq-filter #'file-exists-p
                    (delete-dups (mapcar #'expand-file-name
                                         (cons my/gtd-file my/org-agenda-source-files))))))

(defun my/org-source-label (file)
  "Return the repository-derived display label for FILE."
  (let* ((directory (file-name-directory (file-truename file)))
         (root (or (locate-dominating-file directory ".git") directory))
         (name (file-name-nondirectory (directory-file-name root))))
    (or (cdr (assoc name my/org-source-label-alist)) name)))

(defun my/org-agenda-file-p (file)
  "Return non-nil when FILE is one of `org-agenda-files'."
  (and file
       (seq-some (lambda (candidate)
                   (and (file-exists-p candidate)

*** Task states and archives

The complete state flow is =TODO → NEXT → WAIT → DONE/CANCELLED=.
=TODO= is backlog, =NEXT= is deliberately selected work, and =WAIT=
means an external dependency.  An unscheduled =TODO= already covers
paused work, so there is no separate =HOLD= state.

Cookie syntax in the keyword definitions:
- =(t)= / =(n)= / etc — single-letter quick-pick when cycling state.
- =@= — prompt for a multi-line note on entry to the state.
- =!= — stamp a timestamp on entry.
- =@/!= — note on entry, just timestamp on exit.

So =WAIT(w@/!)= reads as "press =w= to set =WAIT=, record what is
being awaited, and log when the wait ends".  =CANCELLED= asks for a
reason.  Terminal work can be moved to the source file's sibling
=todo.org_archive=.

#+BEGIN_SRC elisp
(with-eval-after-load 'org
  (setq org-todo-keywords
        '((sequence "TODO(t)" "NEXT(n)" "WAIT(w@/!)"
                    "|" "DONE(d!)" "CANCELLED(c@)"))
        org-log-into-drawer t
        org-log-done 'time
        org-archive-location "%s_archive::"))
#+END_SRC

*** Today's-heading helper

Journal captures land under today's =** <YYYY-MM-DD Day>= heading
inside =* Journal=.  =my/gtd-today-heading= guarantees that anchor
exists and positions point on it.  Quick tasks do not use this helper;
they go to =* Inbox= instead.

Two subtle pieces:

1. The =\\s-*$= regex matches up to end-of-line; =re-search-forward=
   leaves point at /end of match/, which on a =^...$= regex is the
   start of the /next/ line.  =goto-char (match-beginning 0)= snaps
   back to the heading itself.
2. Don't wrap the body in =org-with-wide-buffer= — that macro
   restores point on exit, which is exactly what capture does NOT
   want (the whole point is to leave point in place for the caller).

#+BEGIN_SRC elisp
(defun my/gtd-today-heading ()
  "Position point on today's `** <date>' heading inside `* Journal'.
Create the journal anchor and today's subheading when missing.  Used
by the journal capture template with a `file+function' target.

NOTE: do not wrap the body in `org-with-wide-buffer' — that macro
restores point on exit, which defeats the whole point of positioning
it for the caller."
  ;; `file+function' targets already enter the file's buffer before
  ;; calling us; the `set-buffer' here is for direct callers (tests,
  ;; manual invocations).
  (set-buffer (find-file-noselect my/gtd-file))
  (widen)
  (goto-char (point-min))
  (unless (re-search-forward "^\\* Journal\\s-*$" nil t)
    ;; No anchor yet. Create `* Journal' at end of file with a blank
    ;; line above (if there's any content) and one below.
    (goto-char (point-max))
    (unless (bolp) (insert "\n"))
    (unless (or (bobp) (save-excursion (forward-line -1) (looking-at-p "^\\s-*$")))
      (insert "\n"))
    (insert "* Journal\n\n"))
  (org-back-to-heading t)
  (let* ((journal-position (point))
         (journal-end (save-excursion (org-end-of-subtree t t) (point)))
         (today (format-time-string "<%Y-%m-%d %a>"))
         (heading (concat "** " today)))
    (if (re-search-forward
         (concat "^" (regexp-quote heading) "\\s-*$") journal-end t)
        ;; Existing heading — re-search-forward leaves point at end of
        ;; match (which on a `^...$' regexp is the start of the *next*
        ;; line); use match-beginning to land back on the heading itself.
        (goto-char (match-beginning 0))
      ;; Missing. Append at the end of `* Journal' with one blank line
      ;; before and after, then land on the new heading line.
      (goto-char journal-position)
      (org-end-of-subtree t t)
      ;; Ensure exactly one blank line between previous content and the
      ;; new heading.
      (unless (bolp) (insert "\n"))
      (unless (save-excursion (forward-line -1) (looking-at-p "^\\s-*$"))
        (insert "\n"))
      (insert heading "\n\n")
      (forward-line -2))))
#+END_SRC

*** Local task dashboard

The dashboard is a read-only projection of the same active headings
used by Agenda.  Emacs exports generated JSON; a loopback-only Python
server serves the static board and lets a card open its source heading
through =emacsclient=.  The browser never parses or writes Org files.

No persistent Org IDs are required.  Export-time identifiers only join
the displayed card to the file and line in the same generated payload.
The server accepts an identifier, resolves it itself, and invokes
=emacsclient= without a shell.

(defun my/org-dashboard--entry-timestamp ()
  "Return the first active timestamp in the current entry body.
Planning and closing timestamps are returned through their dedicated
fields instead."
  (save-excursion
    (let ((end (org-entry-end-position))
          found)

  "Return active task records for export GENERATION.
Generation-scoped identifiers make stale browser cards fail closed."
  (require 'org)
  (let ((counter 0)
        tasks)
    (dolist (file org-agenda-files)
      (with-current-buffer (find-file-noselect file)
        (org-with-wide-buffer
         (org-map-entries

                        (timestamp . ,(or (my/org-dashboard--entry-timestamp) :null)))

          nil 'file))))

(defun my/org-dashboard-export ()
  "Atomically export active Org tasks for the local dashboard.
Return `my/org-dashboard-data-file'."
  (interactive)
  (let* ((target (expand-file-name my/org-dashboard-data-file))
         (directory (file-name-directory target))
         (generation
          (substring
           (secure-hash 'sha256
                        (format "%s:%s:%s" (current-time) (emacs-pid) (random)))
           0 16))
         (payload `((schemaVersion . 1)
                    (generation . ,generation)
                    (generatedAt . ,(format-time-string "%Y-%m-%dT%H:%M:%S%z"))
                    (tasks . ,(vconcat (my/org-dashboard--collect-tasks generation)))))
         temporary)
    (make-directory directory t)
    (setq temporary (make-temp-file (expand-file-name ".tasks-" directory)))
    (unwind-protect
        (progn
          (with-temp-file temporary
            (insert (json-serialize payload)))
          (rename-file temporary target t)
          (setq temporary nil))
      (when (and temporary (file-exists-p temporary))
        (delete-file temporary)))
    (when (called-interactively-p 'interactive)
      (message "Exported Org tasks to %s" target))
    target))

(defun my/org-dashboard--start-server ()

             :noquery t))))

** Readable wide tables

A table wider than the window is hard to read: Org truncates its
lines and Markdown wraps them.  The source buffers keep their
wrapping, so that prose wraps as before (decision D15 in
=docs/work/README.org=).  Two tools make wide tables readable; the
[[file:docs/how-to/wide-tables.org][how-to]] shows how to use them.

In Org, width cookies such as =<20>= narrow columns, and =M-x
org-table-header-line-mode= shows the header row on the top line of
the window once it has scrolled off.  The mode stays off by default:
Org runs it after every command, with a =redisplay= each time, and its
loop over rule rows never ends when the table at the top of the window
holds only rules up to an end of buffer without a final newline, as
when typing =|-= in a new file.  =C-g= cannot stop it.

For Org and Markdown alike, =C-c v t= opens the table at point in a
read-only =tabulated-list-mode= view: a box with a border around every
cell, every cell in full, sortable columns, and =RET= to go back to the
cell in the source.  The columns fit the window: when the table is
wider, its widest columns narrow to a common width, never below
=my/table-view-min-width=, and their cells wrap onto as many lines as
they need, between words.  A table still too wide scrolls sideways.
=g= fits the view again after its window changed size, and =}= and ={=
widen or narrow the column at point, so its cells wrap less or more.
Org tables are read by =org-table-to-lisp=, Markdown pipe tables by
the small parser below.  The first row is the header when a rule
follows it, else the columns are named =$1=, =$2= and so on, as Org
references them.  Rows of Org width and alignment cookies, =<>= included, are hidden,
as Org export hides them (=org-export-table-row-is-special-p=).

In Emacs 31 the header line of a tabulated list stays in place when
its rows scroll horizontally.  The view computes its own header line
from =window-hscroll=, and sets it again after every command, because
sorting and the column-width commands set the tabulated-list one.
=C-x <= (=scroll-left=) is a disabled command in vanilla Emacs; it is
enabled here, in every buffer and on purpose, since scrolling sideways
is how the view is read.

The Org header overlay belongs to the buffer, not to a window, and Org
puts it on the line at the top of the selected window even when point
is on that line: typing there edits a row the header hides, and
another window showing that line shows the header in its place.  The
how-to lists this under Limits.

#+BEGIN_SRC elisp
(put 'scroll-left 'disabled nil)

(defun my/table-view-org-rows ()
  "Return the rows of the Org table at point, or nil when there is none.
A row is `hline' for a rule, or for a row of width and alignment
cookies such as <20> or <>, which Org export hides too.  Any other row is
\(MARKER . CELLS): a marker at the start of its line, and its cells
as `org-table-to-lisp' reads them, without text properties."
  (when (org-at-table-p)
    (save-excursion
      (goto-char (org-table-begin))
      ;; `org-table-to-lisp' reads one row per line from the beginning.
      (mapcar (lambda (row)
                (prog1 (if (or (eq row 'hline)
                               (and (seq-every-p (lambda (cell)
                                                   (string-match-p
                                                    "\\`\\(?:<[lrc]?[0-9]*>\\)?\\'" cell))
                                                 row)
                                    (seq-some (lambda (cell) (string-prefix-p "<" cell))
                                              row)))
                           'hline
                         (cons (copy-marker (point)) (mapcar #'substring-no-properties row)))
                  (forward-line)))
              (org-table-to-lisp)))))

(defun my/table-view-markdown-rows ()
  "Return the rows of the Markdown pipe table at point, or nil.
The table is the run of lines that start with a pipe, after any
indentation.  A row is `hline' for the alignment row, such as |:--|--:|,
which is the second line: dashes on any other line are data.
Any other row is (MARKER . CELLS): a marker at the start of its line,
and its cells, trimmed.  A pipe after a backslash belongs to its cell,
without the backslash; the pipe that ends a line is optional."
  (save-excursion
    (beginning-of-line)
    (when (looking-at-p "[ \t]*|")
      ;; The table starts after the closest line above that is not a
      ;; table line: a blank line, or one starting with another character.
      (goto-char (if (re-search-backward "^[ \t]*[^| \t]" nil t) (pos-bol 2) (point-min)))
      (let ((rows nil))
        (while (looking-at "[ \t]*|")
          (let ((start (match-end 0))
                (cells nil))
            (goto-char start)
            (while (search-forward "|" (pos-eol) t)
              (unless (eq (char-before (1- (point))) ?\\)
                (push (buffer-substring-no-properties start (1- (point))) cells)
                (setq start (point))))
            (push (buffer-substring-no-properties start (pos-eol)) cells)
            (setq cells (mapcar (lambda (cell) (string-replace "\\|" "|" (string-trim cell)))
                                (nreverse (if (string-blank-p (car cells)) (cdr cells) cells))))
            (push (if (and cells
                           (length= rows 1)
                           (seq-every-p (lambda (cell) (string-match-p "\\`:?-+:?\\'" cell))
                                        cells))
                      'hline
                    (cons (copy-marker (pos-bol)) cells))
                  rows))
          (forward-line))
        (nreverse rows)))))

(defcustom my/table-view-min-width 10
  "Narrowest width, in columns, to which the table view fits a column.
A table wider than its window even with its columns this narrow
scrolls sideways."
  :type 'natural
  :group 'my)

(defvar-local my/table-view--natural-widths nil
  "Natural width of each column of the table view: its widest cell or label.")

(defun my/table-view-widths ()
  "Return the widths of the columns of the table view, each at least 2.
Below 2 columns a wide character could not fit, and cells and borders
would no longer line up."
  (mapcar (lambda (column) (max 2 (cadr column))) tabulated-list-format))

(defun my/table-view-wrap (text width)
  "Return the lines of TEXT broken between words, at most WIDTH columns wide.
WIDTH is at least 2, the width of the widest character.  Runs of blanks
become one space.  A word wider than WIDTH is cut into pieces of WIDTH
columns.  An empty TEXT gives one empty line."
  (let ((lines nil)
        (line nil))
    (dolist (word (split-string text "[ \t]+" t))
      (if (and line (<= (+ (string-width line) 1 (string-width word)) width))
          (setq line (concat line " " word))
        (when line
          (push line lines))
        (while (> (string-width word) width)
          (let ((head (truncate-string-to-width word width)))
            (push head lines)
            (setq word (substring word (length head)))))
        (setq line word)))
    (nreverse (cons (or line "") lines))))

(defun my/table-view-rule (widths names left middle right)
  "Return a horizontal rule of the table view, with its newline.
WIDTHS and NAMES are those of the columns; LEFT, MIDDLE and RIGHT are
the characters at the left edge, between two columns and at the right
edge.  The part of each column carries its name, as its cells do, so
that sorting and moving by column also work on a rule."
  (concat
   (cl-loop for width in widths
            for name in names
            for edge = left then middle
            concat (propertize (concat edge (make-string (+ width 2) ?─))
                               'tabulated-list-column-name name 'face 'shadow))
   (propertize right 'tabulated-list-column-name (car (last names)) 'face 'shadow)
   "\n"))

(defun my/table-view-print-entry (id cells)
  "Insert the row ID of CELLS as lines of a box, under the rule above it.
This is the `tabulated-list-printer' of `my/table-view-mode'.  Each
cell wraps to the width of its column, so a row is as tall as its
tallest cell.  A row ends the table with the bottom rule, which the
next row turns into the rule between the two.  Every line of the row,
the rule above it included, carries the row's id and cells; each
column's part of a line, its left border included, carries the
column's name.  Padding aligns each border with `:align-to', so the
borders stay in line whatever the width of the glyphs."
  (let* ((widths (my/table-view-widths))
         (names (mapcar #'car tabulated-list-format))
         (pieces (seq-mapn #'my/table-view-wrap cells widths))
         (next-borders (let ((x 0))
                         (mapcar (lambda (width) (setq x (+ x width 3))) widths)))
         (first (bobp))
         (start (if first (point) (pos-bol 0))))
    (delete-region start (point))
    (insert (my/table-view-rule widths names
                                (if first "┌" "├") (if first "┬" "┼") (if first "┐" "┤")))
    (dotimes (line (apply #'max (mapcar #'length pieces)))
      (insert (cl-loop for name in names
                       for column in pieces
                       for border in next-borders
                       concat (propertize
                               (concat (propertize "│" 'face 'shadow) " "
                                       (or (nth line column) "")
                                       (propertize " " 'display `(space :align-to ,border)))
                               'tabulated-list-column-name name))
              (propertize "│" 'face 'shadow 'tabulated-list-column-name (car (last names)))
              "\n"))
    (add-text-properties start (point)
                         `(tabulated-list-id ,id tabulated-list-entry ,cells))
    (insert (my/table-view-rule widths names "└" "┴" "┘"))))

(defun my/table-view-header-line ()
  "Return the header line of the table view: the labels, between bars.
Each label is drawn with `:align-to' where the cells of its column
start, so that later labels stay above their cells whatever the width
of the glyphs, and shifts left with `window-hscroll'; the part of a
label left of the window is cut off.  A label wider than its column
ends with an ellipsis.  The header line is a mode-line construct, so a
% in a label is escaped."
  (let* ((hscroll (window-hscroll))
         (widths (my/table-view-widths))
         (bar (propertize "│" 'face 'shadow))
         (x 0)
         (borders (mapcar (lambda (width) (prog1 x (setq x (+ x width 3)))) widths)))
    (cl-flet ((at (column)
                (propertize " " 'display `(space :align-to (+ header-line-indent-width
                                                              ,(max 0 (- column hscroll)))))))
      (concat
       (cl-loop for width in widths
                for border in borders
                for column across tabulated-list-format
                concat (concat
                        (when (>= border hscroll)
                          (concat (at border) bar))
                        (at (+ border 2))
                        (string-replace
                         "%" "%%"
                         (truncate-string-to-width
                          (truncate-string-to-width (car column) width nil nil t)
                          width (max 0 (- hscroll border 2))))))
       (when (>= x hscroll)
         (concat (at x) bar))))))

(defconst my/table-view-header-line-format '(:eval (my/table-view-header-line))
  "Header line format of `my/table-view-mode'.")

(defun my/table-view-fit ()
  "Fit the columns of the table view to the width of the selected window.
When the natural widths, those of the widest cell or label of each
column, fit, the columns keep them.  Otherwise the widest columns
narrow to the largest common width that fits, but not below
`my/table-view-min-width', and their cells wrap; a table wider still
scrolls sideways."
  (let* ((naturals my/table-view--natural-widths)
         (available (- (window-body-width) 2 (* 3 (length naturals))))
         (limit (apply #'max naturals)))
    (while (and (> limit my/table-view-min-width)
                (> (apply #'+ (mapcar (lambda (natural) (min natural limit)) naturals))
                   available))
      (setq limit (1- limit)))
    (cl-loop for column across tabulated-list-format
             for natural in naturals
             do (setf (cadr column) (min natural limit)))))

(define-derived-mode my/table-view-mode tabulated-list-mode "Table"
  "Major mode viewing an Org or Markdown table as a box of wrapped cells.
Every cell is shown in full, wrapped to the width of its column; the
columns fit the window when they can.  The view is read-only: edit the
table in its source.  The header line follows horizontal scrolling.

\\{my/table-view-mode-map}"
  (setq-local tabulated-list-printer #'my/table-view-print-entry)
  (setq header-line-format my/table-view-header-line-format)
  ;; `revert-buffer' (g) fits the columns to a window that changed size.
  (add-hook 'tabulated-list-revert-hook #'my/table-view-fit nil t)
  ;; Sorting and the column-width commands set the header line of
  ;; `tabulated-list-init-header', which does not scroll horizontally.
  (add-hook 'post-command-hook
            (lambda () (setq header-line-format my/table-view-header-line-format))
            nil t))

(defun my/table-view ()
  "Show the Org or Markdown table at point in a read-only box of cells.
Each row of the table is a row of the box, with every cell in full,
wrapped to fit the window.
\\<my/table-view-mode-map>In the box, \\[tabulated-list-sort] sorts by the column at point,
and \\[my/table-view-goto-source] goes back to the cell in the table."
  (interactive)
  (let* ((rows (seq-drop-while
                (lambda (row) (eq row 'hline))
                (or (cond ((derived-mode-p 'org-mode) (my/table-view-org-rows))
                          ((derived-mode-p 'markdown-mode) (my/table-view-markdown-rows)))
                    (user-error "No Org or Markdown table at point"))))
         (header (and (eq (cadr rows) 'hline) (cdar rows)))
         (data (seq-remove (lambda (row) (eq row 'hline)) (if header (cddr rows) rows)))
         (count (apply #'max (length header) (mapcar (lambda (row) (length (cdr row))) data)))
         (entries (mapcar (lambda (row)
                            (list (car row)
                                  (vconcat (cdr row)
                                           (make-list (- count (length (cdr row))) ""))))
                          data)))
    (when (zerop count)
      (user-error "No row in the table at point"))
    (with-current-buffer (get-buffer-create (format "*Table: %s*" (buffer-name)))
      (my/table-view-mode)
      (setq tabulated-list-entries entries
            tabulated-list-format
            (vconcat
             (mapcar (lambda (column)
                       ;; Sorting finds a column by its label: make labels unique.
                       (let ((label (or (nth column header) "")))
                         (when (or (string-empty-p label)
                                   (member label (cdr (member label header))))
                           (setq label (format "$%d" (1+ column))))
                         (list label
                               (apply #'max (string-width label)
                                      (mapcar (lambda (entry)
                                                (string-width (aref (cadr entry) column)))
                                              entries))
                               t)))
                     (number-sequence 0 (1- count))))
            my/table-view--natural-widths (mapcar #'cadr tabulated-list-format))
      (my/table-view-fit)
      (tabulated-list-print)
      (pop-to-buffer-same-window (current-buffer)))))

(defun my/table-view-goto-source ()
  "Go to the cell at point in the source table."
  (interactive)
  (let ((line (tabulated-list-get-id))
        (column (seq-position (mapcar #'car tabulated-list-format)
                              ;; At the end of a line, the last cell.
                              (or (get-text-property (point) 'tabulated-list-column-name)
                                  (get-text-property (max (pos-bol) (1- (point)))
                                                     'tabulated-list-column-name)))))
    (unless (and line (buffer-live-p (marker-buffer line)))
      (user-error "No row of a live table at point"))
    (pop-to-buffer-same-window (marker-buffer line))
    (goto-char line)
    (if (derived-mode-p 'org-mode)
        (org-table-goto-column (1+ (or column 0)))
      (markdown-table-goto-column (1+ (or column 0))))))

** File manager

[[https://github.com/alexluigit/dirvish][dirvish]] is a polished layer on top of =dired= that adds:

- A *three-pane layout*: parent directory on the left, current directory
  in the middle, file preview on the right. Toggle it with =M-t=.
- File-type icons (nerd-icons), git status, timestamps, and sizes as
  column attributes.  These are the only icons of Dired buffers:
  treemacs-icons-dired would draw a second icon on each line, so
  Treemacs keeps its icons to its own buffer.
- =dirvish-fd= (=C-c f=) for interactive fuzzy file search via =fd=.
- Files dropped from other programs land in the listed directory.
  Dragging files out of Dired works only where Emacs can start a drag,
  in the macOS and X11 builds; the pgtk build cannot.
- Quick operations: yank menu (=y=), mark menu (=M-m=), sort menu (=s=),
  vc menu (=v=).

The default layout shows *one parent directory* on the left and a *preview
pane* on the right (55% of the frame). Press =M-t= to toggle between
it and a single window, =M-T= to go through the layouts of
=dirvish-layout-recipes=, and =M-s= for an interactive setup menu
that persists for the session. Directories are always sorted first
(=--group-directories-first=); =.= and =..= are hidden (=-A=).

[[https://github.com/alexluigit/dirvish][dirvish]] overrides =dired= completely — any call to =C-x d= or
=find-file= on a directory opens dirvish.

Loading strategy is deliberately decoupled from =transient=.  Previously
=use-package dirvish :after transient= deferred *everything* until
=transient= was loaded, including the =dirvish-override-dired-mode=
call that lives inside =with-eval-after-load 'dirvish=.  If any
code-path opened a dired buffer before =transient= loaded, the user
saw plain dired instead of dirvish — a non-deterministic outcome
depending on load ordering.

The new strategy:

- =use-package dirvish= has no =:after=.  Dirvish itself =(require
  'transient)= at top-level so it pulls transient in when first
  loaded.
- =emacs-startup-hook= loads dirvish and activates
  =dirvish-override-dired-mode= eagerly, immediately after init
  completes.  Previous attempts to defer the override via a one-shot
  =dired-mode-hook= had a fatal race: =dired-mode-hook= fires /during/
  =dired-noselect='s setup of the buffer being constructed, after the
  buffer has already been built without the override advice.  A
  code path like =C-x C-f <some-dir>= → =find-file-noselect= →
  =dired-noselect= would produce a plain dired buffer; the override
  only kicked in for /subsequent/ dired operations, leaving stranded
  plain-dired buffers.  The eager activation is unconditional and
  costs ~25 ms at startup — the same load that used to be paid on
  the first dired action, just shifted earlier.
- =dirvish-fd= is autoloaded by dirvish, so =C-c f= works before any
  dired activity.

Dired's own settings live in a block of their own, so that removing
dirvish never changes them: deleted files go to the trash, files can
be dragged out of Dired, and selected text out of any buffer, to other
programs where the build can start a drag, and the listing shows
directories first.

**** Collapsed chains

The =collapse= attribute shows a chain of directories that each hold
a single entry on the line of its first directory, as IntelliJ does
for Java packages: =src › main › java › App.java=.  Only the line's
display changes; its text, which =dired-get-filename= reads, is still
the first directory.

Upstream counts every entry, so a hidden =.gitkeep= or =.DS_Store=
ends a chain, and =TAB= expands only the first directory.  Here one
rule, =my/dirvish-collapse-chain=, decides what a chain is, ignoring
dotfiles and the entries =dired-omit-mode= hides, and never starting
at the =.= and =..= lines that =M-l= can show.  It matches the omit
regexp with the buffer's =case-fold-search=, as upstream's subtree
does, not with =dired-omit-case-fold-p=: on a case-sensitive file
system an upper-case =X.ELC= that the listing shows ends no chain.  Where the attribute
draws chains (=my/dirvish-collapse-shown-p=: =collapse= is on in =M-s=,
and the listing is local and not an fd result), three places use it:
- the =collapse= attribute draws it;
- =TAB= (=my/dirvish-subtree-toggle-chain=) expands every level of
  it, down to the contents of its last directory;
- =RET= (=my/dirvish-collapse-find-entry=) visits its last entry,
  through =dired--find-possibly-alternative-file=, the internal of
  =dired-find-file= that takes a file name; a scenario visits a chain
  from the full-frame layout.

The attribute's rule lives in the private =dirvish-collapse--cache=,
which an =:override= advice replaces.  Like the subtree helpers below,
it depends on dirvish internals: =tests/file-manager-test.el= is a
canary that fails as soon as any of them changes upstream.

#+BEGIN_SRC elisp
(defun my/dirvish-collapse-chain (dir)
  "Return the chain of single visible entries under DIR, top first.
A directory continues the chain when it holds exactly one visible
entry: not a dotfile, and not hidden by `dired-omit-mode' when it is
on in the current buffer.  The chain ends at a file, at a directory
with no or several visible entries, before an entry it already went
through, as in a link to a parent, and before a link that does not
resolve, as in a link to itself.  It is nil when DIR is not a
directory holding exactly one visible entry, and for the . and ..
entries of a listing, as upstream: they name the current directory
and its parent, not a chain."
  (when (and (file-directory-p dir)
             (not (member (file-name-nondirectory (directory-file-name dir))
                          '("." ".."))))
    (let ((omit (let ((regexp (and (bound-and-true-p dired-omit-mode)
                                   (dired-omit-regexp))))
                  (if (seq-empty-p regexp) regexp-unmatchable regexp)))
          (seen (list (file-truename dir)))
          (chain nil))
      ;; `directory-files' fails on a file or a link loop: the chain ends.
      (while-let ((entries (seq-remove (lambda (name)
                                         (or (string-prefix-p "." name)
                                             (string-match-p omit name)))
                                       (ignore-errors (directory-files dir))))
                  ((null (cdr entries)))
                  ;; Not `expand-file-name', which reads an entry named
                  ;; ~ as the home directory.
                  (next (concat (file-name-as-directory dir) (car entries)))
                  (truename (ignore-errors (file-truename next)))
                  ((not (member truename seen))))
        (push truename seen)
        (push next chain)
        (setq dir next))
      (nreverse chain))))

(with-eval-after-load 'dirvish-collapse
  (define-advice dirvish-collapse--cache (:override (f-name) my/visible-chain)
    "Describe the chain `my/dirvish-collapse-chain' finds under F-NAME.
Return what upstream returns: (HEAD . TAIL) for a chain, where TAIL
is its last entry and HEAD the separators and directories before it;
\(empty . t) for an empty directory; (nil . nil) otherwise."
    (dirvish-attribute-cache f-name
        (if (bound-and-true-p dired-omit-mode) :my/collapse-omit :collapse)
      (let* ((chain (my/dirvish-collapse-chain f-name))
             (names (mapcar #'file-name-nondirectory chain))
             (head (apply #'concat dirvish-collapse-separator
                          (mapcar (lambda (name) (concat name dirvish-collapse-separator))
                                  (butlast names))))
             (tail (car (last names))))
        (cond (chain
               (add-face-text-property 0 (length head) 'dirvish-collapse-dir-face nil head)
               (add-face-text-property 0 (length tail)
                                       (if (file-directory-p (car (last chain)))
                                           'dirvish-collapse-dir-face
                                         'dirvish-collapse-file-face)
                                       nil tail)
               (cons head tail))
              ((ignore-errors (directory-empty-p f-name)) (cons 'empty t))
              (t (cons nil nil)))))))

(defun my/dirvish-collapse-shown-p ()
  "Non-nil when the current dirvish buffer draws the `collapse' attribute.
dirvish draws it while it is among the session's attributes, which
\\[dirvish-setup-menu] changes, in a local listing that is not an fd
result, as the attribute's `:when' says."
  (and (assq 'collapse (dirvish-prop :attrs))
       (not (dirvish-prop :fd-info))
       (not (dirvish-prop :remote))))

(defun my/dirvish-subtree-toggle-chain ()
  "Expand or collapse the directory at point, a collapsed chain at once.
On a directory whose line shows a chain, as `my/dirvish-collapse-chain'
finds it, expand every level of the chain, down to the contents of
its last directory.  Elsewhere, and to collapse, act as
`dirvish-subtree-toggle'."
  (interactive)
  (let* ((file (dired-get-filename nil t))
         (chain (and file (not (dirvish-subtree--expanded-p))
                     (my/dirvish-collapse-shown-p)
                     (my/dirvish-collapse-chain file)))
         (end (car (last chain))))
    (if (not chain)
        (dirvish-subtree-toggle)
      (save-excursion
        (dirvish-subtree-expand-to end)
        (when (file-directory-p end)
          (dirvish-subtree-toggle))))))

(defun my/dirvish-collapse-find-entry ()
  "Visit the file or directory at point, or the end of its collapsed chain.
On a directory whose line shows a chain, as `my/dirvish-collapse-chain'
finds it, visit the chain's last entry, the one its line shows last, as
`dired-find-file' visits the entry at point: through dirvish, which
leaves its full-frame layout for a file.  When that entry does not

  (interactive)

            ((my/dirvish-collapse-shown-p))
            (end (car (last (my/dirvish-collapse-chain file))))
            ((file-exists-p end)))
      (dired--find-possibly-alternative-file end)
    (call-interactively #'dired-find-file)))

**** Subtree helpers

Three interactive commands operating on the subtree under point:
- =my/dirvish-subtree-expand-all-children= :: expand a directory and every
  nested sub-directory inside it recursively.
- =my/dirvish-subtree-collapse-all= :: collapse every expanded subtree in the
  buffer (snapshot the overlay list first so iteration is stable).
- =my/dirvish-subtree-toggle-all= :: collapse if the directory at point is
  expanded; otherwise delegate to =expand-all-children=.  Bound to =<S-TAB>=.

#+BEGIN_SRC elisp
(with-eval-after-load 'dirvish
  ;; Expand the directory at point and all its nested sub-directories.
  ;; Guard with when-let: dired-get-filename returns nil on blank/header lines.
  (defun my/dirvish-subtree-expand-all-children ()
    "Expand directory at point and every nested sub-directory within it."
    (interactive)
    (when-let ((file (dired-get-filename nil t)))
      (when (file-directory-p file)
        (unless (dirvish-subtree--expanded-p)
          (dirvish-subtree-toggle))
        (save-excursion
          (forward-line 1)
          (while (and (not (eobp)) (dirvish-subtree--parent))
            (when-let ((f (dired-get-filename nil t)))
              (when (and (file-directory-p f)
                         (not (dirvish-subtree--expanded-p)))
                (dirvish-subtree-toggle)))
            (forward-line 1))))))
  ;; copy-sequence snapshots the overlay list so toggling doesn't corrupt iteration.
  (defun my/dirvish-subtree-collapse-all ()
    "Collapse every expanded subtree in the buffer."
    (interactive)
    (save-excursion
      (dolist (ov (copy-sequence dirvish-subtree--overlays))
        (when (overlay-buffer ov)
          (goto-char (max (point-min) (1- (overlay-start ov))))
          (beginning-of-line)
          (dirvish-subtree-toggle)))))
  (defun my/dirvish-subtree-toggle-all ()
    "Collapse directory at point if expanded; otherwise expand it and all children."
    (interactive)
    (when-let ((file (dired-get-filename nil t)))
      (when (file-directory-p file)
        (if (dirvish-subtree--expanded-p)
            (dirvish-subtree-toggle)
          (my/dirvish-subtree-expand-all-children))))))

** Bulk editing search results (embark → wgrep)

The most powerful workflow — equivalent to IntelliJ's "Find and
Replace in Files" or Helm's editable grep — is:

1. Run a search: =C-c s r= (=consult-ripgrep=) and type your query.
2. Export candidates to an editable buffer: press =C-c e= while the
   minibuffer is open → =embark-export= creates a =*grep*= buffer
   with all matching lines.
3. Enter wgrep mode: =C-c C-p= → every match line becomes editable.
4. Edit freely: use =M-%= (query-replace), multiple-cursors, or manual
   edits. Changes apply to the originating source files.
5. Apply: =C-c C-c= → saves all edits back to the files.
   Abort:  =C-c C-k= → discards all pending changes.
6. =C-x s= → =save-some-buffers= to persist to disk.

The same works from a =consult-line= buffer search: export the matching
lines, switch to wgrep, edit, and apply. For context lines around each
match, use =consult-grep= with a =-C 2= option in the =--= extra args
slot when prompted.

| Key     | Context      | Command                    | Description                     |
|---------+--------------+----------------------------+---------------------------------|
| =C-c e=   | minibuffer   | embark-export              | Export search results to buffer |
| =C-.=     | anywhere     | embark-act                 | Act on candidate at point       |
| =C-;=     | anywhere     | embark-dwim                | Default action on candidate     |
| =C-c C-p= | grep buffer  | wgrep-change-to-wgrep-mode | Make grep buffer editable       |
| =C-c C-c= | wgrep buffer | wgrep-finish-edit          | Apply edits to source files     |
| =C-c C-k= | wgrep buffer | wgrep-abort-changes        | Discard all pending changes     |

** Display changes in place

diff-hl highlights VCS-modified lines in the fringe.  It replaces
git-gutter + git-gutter-fringe which created one overlay per modified
line through fringe-helper, causing O(n) redisplay overhead in large
diff hunks (see finding 027).  diff-hl's modification-hooks handler
is a cheap teardown (delete overlays, defer re-render to idle), and
it has no fringe-helper dependency.

To diff an unsaved buffer, or to revert, stage or show a hunk, diff-hl
first writes the reference revision to a copy in =/dev/shm=.  It names
that copy after the whole path of the file, with =!= for =/=, so a deep
path gives a name longer than the 255 bytes a file name may have: the
copy is never written, the diff fails, and Emacs warns =Unlocking
file: File name too long= at each refresh.  The advice below replaces
the name by its SHA-1, which is what Emacs does for auto-save files
when a transform of =auto-save-file-name-transforms= ends in =sha1=
rather than =t=.

#+BEGIN_SRC elisp
(defun my/diff-hl-hash-temp-file-name (name)
  "Return NAME with its base name replaced by its SHA-1.
diff-hl names its copy of a revision after the full path of the
file; for a deep path that name passes the 255-byte limit of a
file name, so the copy is never written and the diff fails."
  (expand-file-name (concat "#" (sha1 (file-name-nondirectory name)) "#")
                    (file-name-directory name)))

;; diff-hl: fringe indicators for VCS changes.
;; Keybindings preserve the C-c g prefix from the previous git-gutter config.
;; Keep Git change markers on the right fringe.
(use-package diff-hl
  :hook ((prog-mode  . diff-hl-mode)
         (conf-mode  . diff-hl-mode)
         (text-mode  . diff-hl-mode)
         (dired-mode . diff-hl-dired-mode))
  :bind (("C-c g n" . diff-hl-next-hunk)
         ("C-c g p" . diff-hl-previous-hunk)
         ("C-c g s" . diff-hl-stage-current-hunk)
         ("C-c g r" . diff-hl-revert-hunk)
         ("C-c g d" . diff-hl-show-hunk))
  :custom
  (diff-hl-side 'right)
  :config
  ;; Live diff against HEAD for unsaved changes (idle timer, async).
  ;; It also replaces diff-hl's teardown of a hunk's overlay on each
  ;; edit by its idle refresh.
  (diff-hl-flydiff-mode 1)
  (advice-add 'diff-hl-make-temp-file-name :filter-return
              #'my/diff-hl-hash-temp-file-name))

** Better diff colouring

Package [[https://github.com/dandavison/magit-delta][magit-delta]] improves the coloring of diffs in magit using
[[https://github.com/dandavison/delta][delta]]. You need to have it installed when you use it in your global
git config, or it will corrupt magit's section hierarchy — expanding
"Unstaged changes" crashes with =magit-section-toggle: Cannot hide
root section=.

#+BEGIN_QUOTE
$ git diff
error: cannot run delta: No such file or directory
fatal: unable to execute pager 'delta'
#+END_QUOTE

delta colours diffs for a dark or a light background, as its =--dark=
or =--light= argument says.  The argument follows the appearance
auto-dark sets, =frame-background-mode=: when magit-delta loads, and
whenever the appearance changes afterwards.

#+BEGIN_SRC elisp
(defun my/magit-delta-follow-appearance ()
  "Make delta colour diffs for the current appearance, light or dark.
The appearance is `frame-background-mode', which auto-dark sets; dark
when it is unset."
  (when (boundp 'magit-delta-delta-args)
    (setq magit-delta-delta-args
          (cons (if (eq frame-background-mode 'light) "--light" "--dark")
                (seq-difference magit-delta-delta-args '("--light" "--dark"))))))

(add-hook 'auto-dark-dark-mode-hook #'my/magit-delta-follow-appearance)
(add-hook 'auto-dark-light-mode-hook #'my/magit-delta-follow-appearance)

(use-package magit-delta
  :after magit
  :hook (magit-mode . magit-delta-mode)
  :custom
  ;; --no-gitconfig: the Nix delta wrapper injects --config with
  ;; side-by-side = true.  That adds structural layout text which
  ;; corrupts magit's section hierarchy ("--side-by-side" "false"
  ;; does NOT work — delta treats "false" as a filename, producing
  ;; zero output).  --no-gitconfig overrides --config and avoids the
  ;; problem entirely.
  (magit-delta-delta-args
   '("--no-gitconfig"
     "--max-line-distance" "0.6"
     "--true-color" "always"
     "--color-only"
     "--syntax-theme" "ansi"))
  :config
  (my/magit-delta-follow-appearance))

** Powerful, efficient code parsing with tree-sitter

Emacs 29+ ships =treesit= (built-in), a binding to the
[[https://tree-sitter.github.io][tree-sitter]] parsing library. Tree-sitter grammars enable precise,
incremental syntax highlighting, structural navigation (=C-== / ~C-M-=~
via =expreg=), and folding (=C-s-<tab>=).

[[https://github.com/renzmann/treesit-auto][treesit-auto]] is kept purely for on-demand grammar installation
(=M-x treesit-auto-install-all=).  It does *not* load at startup and
contributes zero to init time.  The major-mode remapping that
=global-treesit-auto-mode= would otherwise perform is done below via
=my/treesit-remap-when-ready= and =my/treesit-auto-mode-when-ready=
helper functions.  Each remap only fires when the corresponding
tree-sitter grammar is actually installed (checked with
=treesit-ready-p=), preventing "missing grammar" errors on fresh
machines.  This costs under 1 ms and means =treesit-auto= never needs
to be eager.  Without the grammar the original mode runs, and the
helper adds =lsp-deferred= to its hook for Java and Dockerfile.  An
Emacs built without tree-sitter skips this block: there =java-mode= and
=dockerfile-mode= start no language server.

*Note:* =bash= is deliberately excluded from auto-remap to prevent a
subtle breakage where org-mode's temporary =sh-mode= buffers (used for
src-block fontification) fail when remapped to =bash-ts-mode=. Shell
script files (=.sh=, =.bash=, =.zsh=) still open in =bash-ts-mode=
via =auto-mode-alist=.

Run =M-x treesit-auto-install-all= once after a fresh Emacs install to
get all grammars; =treesit-auto= will load lazily at that point.

*macOS + Nix workaround:* Emacs.app (jimeh/emacs-builds) hard-sets
=LIBRARY_PATH= to its bundled GCC framework and the Xcode
CommandLineTools SDK (for =libgccjit= native compilation).  When Nix
GCC compiles tree-sitter grammars, the linker receives =-L= paths
pointing to the Xcode SDK (26.x) while =--sysroot= points to Nix's
Apple SDK (14.4).  The version mismatch means =-lSystem= cannot resolve
and every libc symbol (=malloc=, =free=, =iswspace=, ...) appears
"undefined".  The advice below strips =LIBRARY_PATH= from the
subprocess environment during grammar compilation so Nix GCC falls back
to its own defaults.

#+BEGIN_SRC elisp
(when (fboundp 'treesit-parser-create)
  (require 'treesit)

  ;; Keep grammars in the standard Emacs location:
  ;;   ~/.emacs.d/tree-sitter/
  ;; This makes `treesit-install-language-grammar' and external tools happy.
  (let ((grammar-dir (expand-file-name "tree-sitter/" user-emacs-directory)))
    (make-directory grammar-dir t)
    (add-to-list 'treesit-extra-load-path grammar-dir))

  ;; treesit-auto is kept for on-demand grammar installation only
  ;; (M-x treesit-auto-install-all).  It does NOT need to be loaded at
  ;; startup: major-mode-remap-alist is populated directly below via dolist,
  ;; and auto-install prompting is handled lazily when the package first loads.
  ;; treesit-auto is used for on-demand grammar installation.
  ;; With `use-package-always-defer', its interactive commands are otherwise
  ;; not discoverable via M-x unless the library is required manually.
  (use-package treesit-auto
    :commands (treesit-auto-install-all)
    :config
    (setq treesit-auto-install 'prompt))

  (defun my/treesit-remap-when-ready (lang from to &optional fallback)
    "Remap FROM to TO when LANG grammar is installed.
Otherwise FROM runs: add FALLBACK, when non-nil, to its hook."
    (if (and (treesit-ready-p lang t)
             (fboundp to))
        (add-to-list 'major-mode-remap-alist (cons from to))
      (when fallback
        (add-hook (intern (format "%s-hook" from)) fallback))))

  (defun my/treesit-auto-mode-when-ready (lang regexp mode)
    "Use MODE for REGEXP only when LANG grammar is installed."
    (when (and (treesit-ready-p lang t)
               (fboundp mode))
      (add-to-list 'auto-mode-alist (cons regexp mode))))

  ;; Only remap modes when the corresponding grammar exists.
  ;; This prevents "missing grammar" errors on fresh machines.
  (my/treesit-remap-when-ready 'python     'python-mode     'python-ts-mode)
  (my/treesit-remap-when-ready 'java       'java-mode       'java-ts-mode #'lsp-deferred)
  (my/treesit-remap-when-ready 'json       'js-json-mode    'json-ts-mode)
  (my/treesit-remap-when-ready 'css        'css-mode        'css-ts-mode)
  (my/treesit-remap-when-ready 'html       'html-mode       'html-ts-mode)
  (my/treesit-remap-when-ready 'html       'mhtml-mode      'html-ts-mode)
  (my/treesit-remap-when-ready 'dockerfile 'dockerfile-mode 'dockerfile-ts-mode #'lsp-deferred)

  ;; Extensions that should switch to ts-modes only when ready.
  (my/treesit-auto-mode-when-ready 'yaml       "\\.ya?ml\\'"                                              'yaml-ts-mode)
  (my/treesit-auto-mode-when-ready 'dockerfile "\\(?:Dockerfile\\(?:\\..*\\)?\\|\\.[Dd]ockerfile\\)\\'" 'dockerfile-ts-mode)
  (my/treesit-auto-mode-when-ready 'bash       "\\.sh\\'"                                                'bash-ts-mode)
  (my/treesit-auto-mode-when-ready 'bash       "\\.bash\\'"                                              'bash-ts-mode)
  (my/treesit-auto-mode-when-ready 'bash       "\\.zsh\\'"                                               'bash-ts-mode))

** Folding blocks of text

[[https://github.com/emacs-tree-sitter/treesit-fold][treesit-fold]] uses the tree-sitter syntax tree to fold any language
construct accurately — functions, classes, blocks, doc-comments.
Folding uses inline summaries without fringe indicators. Git change
markers and diagnostics keep their existing fringe placement.

*** Keybindings

A =C-c z= prefix collects all fold actions.  =z= is mnemonic for
"zip", and is otherwise unused in this configuration.  =C-s-<tab>=
remains as a quick toggle for users coming from IDE backgrounds.

| Key       | Command                       | Effect                                    |
|-----------+-------------------------------+-------------------------------------------|
| =C-c z z=   | =treesit-fold-toggle=           | Toggle the node at point                  |
| =C-c z c=   | =treesit-fold-close=            | Close the node at point                   |
| =C-c z o=   | =treesit-fold-open=             | Open the node at point                    |
| =C-c z O=   | =treesit-fold-open-recursively= | Open the node and every child             |
| =C-c z a=   | =treesit-fold-open-all=         | Open every fold in the buffer             |
| =C-c z A=   | =treesit-fold-close-all=        | Close every fold in the buffer            |
| =C-s-<tab>= | =treesit-fold-toggle=           | IDE-style quick toggle (alias of =C-c z z=) |

*** Activation model

Activation is delegated to the package's own =global-treesit-fold-mode=
rather than to ad-hoc =prog-mode-hook= entries: the globalized mode runs
the package's own dispatcher on every major-mode change, which already
encodes the correct "parser ready ∧ supported mode" guard.
=my/treesit-fold-bootstrap= enables the global folding mode once on
=emacs-startup-hook= (after init is otherwise complete; the package
itself is loaded lazily by the hook), and from then on every new
buffer is evaluated automatically.

Folding works in any major mode listed in =treesit-fold-range-alist=
(see =C-h v treesit-fold-range-alist=) provided the corresponding
grammar is installed. =*-ts-mode= major modes create their own parser;
for legacy modes that do not (=clojure-mode=, =nix-mode=, =emacs-lisp-mode=,
=sh-mode= …) =my/treesit-fold-ensure-parser= calls =treesit-parser-create=
opportunistically using the language symbol from
=my/treesit-fold-mode-language-alist=. Add a row in =local.el= to enable
folding in further legacy modes whose grammar is installed.

Run =M-x treesit-auto-install-all= once after a fresh Emacs install to
populate the grammars.

#+BEGIN_SRC elisp
(use-package treesit-fold
  :straight (treesit-fold :type git :host github :repo "emacs-tree-sitter/treesit-fold")
  :hook (emacs-startup . my/treesit-fold-bootstrap)
  :bind (;; IDE-style quick toggle, kept for muscle memory.
         ("C-s-<tab>" . treesit-fold-toggle)
         ;; C-c z = "zip" — the dedicated fold prefix.
         ("C-c z z"   . treesit-fold-toggle)
         ("C-c z c"   . treesit-fold-close)
         ("C-c z o"   . treesit-fold-open)
         ("C-c z O"   . treesit-fold-open-recursively)
         ("C-c z a"   . treesit-fold-open-all)
         ("C-c z A"   . treesit-fold-close-all))
  :init
  ;; Map non-`-ts-mode' major modes to the tree-sitter language whose
  ;; grammar should drive folding.  `treesit-fold-range-alist' itself
  ;; maps mode → (node-type . fn) pairs — it does *not* record which
  ;; grammar to load.  For `*-ts-mode' modes Emacs creates the parser
  ;; automatically; this alist plugs the gap for the legacy modes the
  ;; user actually edits.  Extend it in `local.el' if needed.
  (defvar my/treesit-fold-mode-language-alist
    '((emacs-lisp-mode       . elisp)
      (lisp-interaction-mode . elisp)
      (clojure-mode          . clojure)
      (clojurec-mode         . clojure)
      (clojurescript-mode    . clojure)
      (nix-mode              . nix)
      (sh-mode               . bash)
      (lisp-mode             . commonlisp)
      (json-mode             . json)
      (yaml-mode             . yaml)
      (dockerfile-mode       . dockerfile)
      (markdown-mode         . markdown))
    "Major mode → tree-sitter language for `treesit-fold' fallback.
Used by `my/treesit-fold-ensure-parser' to create a parser in
non-`-ts-mode' buffers whose grammar is installed.  Modes derived
from `*-ts-mode' do not need an entry: the major mode itself creates
the parser.  Languages whose grammar is missing are skipped silently.")

  (defun my/treesit-fold-ensure-parser ()
    "Create a tree-sitter parser so `treesit-fold-mode' can activate.
`treesit-fold-mode' refuses to engage when `(treesit-parser-list)' is
empty, which is the case in non-`-ts-mode' major modes like
`clojure-mode' or `nix-mode'.  When the major mode is in
`my/treesit-fold-mode-language-alist' and the corresponding grammar
is installed, create a parser so folding can engage."
    (when (and (fboundp 'treesit-available-p)
               (treesit-available-p)
               (null (treesit-parser-list))
               (alist-get major-mode treesit-fold-range-alist))
      (when-let* ((lang (alist-get major-mode
                                   my/treesit-fold-mode-language-alist)))
        (when (treesit-ready-p lang t)
          (ignore-errors (treesit-parser-create lang))))))

  (defun my/treesit-fold-bootstrap ()
    "Enable global folding and create parsers for supported legacy modes."
    (require 'treesit-fold)
    (add-hook 'after-change-major-mode-hook
              #'my/treesit-fold-ensure-parser -90)
    (global-treesit-fold-mode 1)))
#+END_SRC

** Indentation level indicators

[[https://github.com/jdtsmith/indent-bars][indent-bars]] replaces the unmaintained =highlight-indent-guides= (last
commit 2021). It uses =display-line-numbers=-style faces, integrates
natively with tree-sitter when a parser is available, and is markedly
cheaper to render in deeply nested buffers.

Enabled by default in every =prog-mode= buffer (which covers Python,
Rust, Java, shell, Yaml-ts, Emacs-Lisp, …). An explicit hook extends
the same treatment to =LaTeX-mode= (a =text-mode= derivative, not
=prog-mode=). Prose buffers do not opt in.

By default =indent-bars= draws the bar via the =:stipple= face
attribute — a per-character bitmap. On the macOS *NS* build of Emacs
30, stipple support is only partial (the upstream patch for full
support landed but is scheduled for Emacs 31, see the indent-bars
[[https://github.com/jdtsmith/indent-bars#compatibility][compatibility table]]). The visible symptom on NS is exactly the
garbled black-and-white block/=-pattern reported here: the depth
palette is computed correctly from the =outline-*= faces, but the
underlying bitmap is mis-rendered, hiding the colour.

The portable workaround recommended by the author is to set
=indent-bars-prefer-character= to =t=, so the bar is painted with a
real glyph (=│=) instead of a stipple. The depth-based colour palette
still applies because it is carried by the face foreground, not by the
stipple bitmap — so we get coloured thin vertical lines that render
correctly on every Emacs build (NS, Cairo, terminal, …) without
needing to detect the platform.

*Per-buffer spacing*

=indent-bars=' built-in spacing guesser
(=indent-bars--guess-spacing=) recognises a long list of major modes,
but it does not include =clojure-mode= / =clojure-ts-mode= — they
derive from =prog-mode=, not =lisp-data-mode=, so the guess falls
through to =standard-indent= (=4= by default). The visible symptom is
4-column-spaced bars in Clojure buffers that do not align with the
2-space form indentation.

=editorconfig= and =dtrt-indent= already discover the buffer's actual
indent width and write it to =lisp-body-indent=,
=python-indent-offset=, =c-basic-offset=, etc. The hook
=my/indent-bars-sync-spacing= bridges that information into
=indent-bars-spacing-override= per buffer: pick the indent variable
that matches the major mode, and if it is set buffer-locally, use its
value. Otherwise leave the override =nil= so =indent-bars=' built-in
guesser keeps working unchanged for everyone else.

*Innermost-bar emphasis*

The bar at the current point's depth is recoloured to the =highlight=
face's *background*. The =:face-bg= flag matters: most themes
(=color-theme-sanityinc-tomorrow= included) define =highlight= with a
=:background= but no explicit =:foreground=, so without =:face-bg= the
=face-foreground= lookup that =indent-bars= performs returns
=unspecified= and the cue silently disappears.

With =:face-bg t=, =indent-bars= reads the =highlight= face's
background colour and uses it as the foreground for the active depth
bar. The cue therefore tracks theme switches automatically (auto-dark
night ↔ day) and contrasts with the depth palette carried by the
=outline-*= faces.

#+BEGIN_SRC elisp
(defun my/indent-bars-sync-spacing ()
  "Set `indent-bars-spacing-override' from the buffer's indent variable.
Bridges per-buffer indent width detected by `editorconfig' or
`dtrt-indent' (or the major mode itself) into the spacing
`indent-bars' uses to draw bars.  When no relevant variable is set
buffer-locally, leave the override `nil' so `indent-bars'' built-in
`indent-bars--guess-spacing' is in charge."
  (let ((width (cond
                ((or (derived-mode-p 'clojure-mode)
                     (derived-mode-p 'clojure-ts-mode)
                     (derived-mode-p 'clojurec-mode)
                     (derived-mode-p 'clojurescript-mode)
                     (derived-mode-p 'lisp-data-mode)
                     (derived-mode-p 'emacs-lisp-mode))
                 (and (boundp 'lisp-body-indent) lisp-body-indent))
                ((or (derived-mode-p 'python-mode)
                     (derived-mode-p 'python-base-mode))
                 (and (boundp 'python-indent-offset)
                      (local-variable-p 'python-indent-offset)
                      python-indent-offset))
                ((derived-mode-p 'sh-base-mode)
                 (and (boundp 'sh-basic-offset)
                      (local-variable-p 'sh-basic-offset)
                      sh-basic-offset))
                ((or (derived-mode-p 'c-mode)
                     (derived-mode-p 'c-ts-base-mode))
                 (and (boundp 'c-basic-offset)
                      (local-variable-p 'c-basic-offset)
                      (numberp c-basic-offset)
                      c-basic-offset)))))
    (when (and (numberp width) (> width 0))
      (setq-local indent-bars-spacing-override width)
      ;; `indent-bars-mode' caches `indent-bars-spacing' in `:setup'
      ;; before this hook runs, so refresh once we have the right value.
      (when (fboundp 'indent-bars-reset)
        (indent-bars-reset)))))

(use-package indent-bars
  :hook ((prog-mode . indent-bars-mode)
         (LaTeX-mode . indent-bars-mode)
         (indent-bars-mode . my/indent-bars-sync-spacing)))
#+END_SRC

** Uniform formatter UI
:PROPERTIES:
:CUSTOM_ID: uniform-formatter-ui
:END:

Formatting is handled by a layered pipeline so that project declared
style always wins over heuristics, and only genuinely modified lines
ever get whitespace cleaned:

1. *editorconfig* — when a =.editorconfig= file is present in the
   project tree it is applied first (see [[Respecting editorconfig]]),
   setting =indent-tabs-mode=, =tab-width=, and =fill-column=
   buffer-locally.
2. *dtrt-indent* — heuristic fallback for files /without/ editorconfig.
   It analyses the file's existing indentation and sets the buffer-local
   indent variables to match, so typing new code respects the dominant
   style already in the file.  Conservative thresholds prevent inference
   on very short or auto-generated files.
3. *ws-butler* — on save, silently strips trailing whitespace
   /only from lines that were modified/ in the current session.  Lines
   you never touched are left exactly as they are, keeping diffs free of
   formatting noise.
4. *apheleia* — runs the project's formatter (isort followed by Black,
   Prettier, shfmt, …) asynchronously on save without moving point.
   Prettier already reads =.prettierrc= / =prettier.config.js= from the project root
   automatically — no extra Emacs configuration is required.

=C-c r= formats the current buffer on demand.

*Formatters used:* =alejandra= (Nix), =isort= then =black= (Python), =shfmt= (shell),
=rustfmt= (Rust), =prettier= (TypeScript/JS/CSS). Java is deliberately excluded: JDTLS
formats via LSP =willSaveWaitUntil= on every save; adding =google-java-format=
as a second pass would fight that and reformat the entire file to Google
style even when the project uses a different convention. Use ~C-c l = =~
(=lsp-format-buffer=) for explicit on-demand LSP formatting.

#+BEGIN_SRC elisp
(use-package apheleia
  :hook ((prog-mode . apheleia-mode)
         (html-mode . apheleia-mode)
         (html-ts-mode . apheleia-mode))
  :config
  (setf (alist-get 'python-mode apheleia-mode-alist) '(isort black))
  (setf (alist-get 'python-ts-mode apheleia-mode-alist) '(isort black))
  (setf (alist-get 'sh-mode apheleia-mode-alist) '(shfmt))
  (setf (alist-get 'alejandra apheleia-formatters) '("alejandra"))
  (setf (alist-get 'nix-mode apheleia-mode-alist) '(alejandra))
  ;; Java is intentionally excluded: JDTLS drives formatting via
  ;; textDocument/willSaveWaitUntil; adding google-java-format as a second
  ;; pass re-indents the entire file on every save regardless of project
  ;; style.  Use C-c l = = (lsp-format-buffer) for explicit on-demand
  ;; formatting.
  (setf apheleia-mode-alist
        (assoc-delete-all 'java-mode apheleia-mode-alist))
  (setf apheleia-mode-alist
        (assoc-delete-all 'java-ts-mode apheleia-mode-alist)))

(keymap-set prog-mode-map "C-c r" #'apheleia-format-buffer)

*** Heuristic indent detection

[[https://github.com/jscheid/dtrt-indent][dtrt-indent]] analyses the existing indentation of a file and sets

**** Learning Python through navigation and inspection

Start with =M-.= to follow a definition and =M-,= to return. Use
=C-c l g i= to enumerate implementations of an abstract method, and
=C-c l G i= to compare them in a peek window. A definition is where a
symbol is defined; a type definition describes its type. Declaration
navigation depends on server support and is not an MRO browser.
=M-x lsp-treemacs-implementations= gives the implementation results as a
tree. Python's server does not currently advertise type hierarchies or
code lenses, so those views cannot reconstruct Python's inheritance order.

[[file:docs/how-to/python.org][Work on a Python project]] gives the keys of each task, from browsing
symbols to evaluating in a stopped frame.

In the REPL, after importing your own class, inspect =MyClass.__mro__=
(or =MyClass.mro()=), =MyClass.__bases__=, =type(value)=, =vars(value)=, and
=help(MyClass)=. =inspect.signature= and =inspect.getsource= connect runtime
objects to their definitions when source is available. Python's
=dis.dis(function)= exposes bytecode if you want to explore execution.
These are ordinary Python tools; no extra Emacs package is needed.

=locals()= at the top-level REPL is not another function's locals. Stop
inside that function with Dape and use =M-x dape-info= to inspect the
available scope buffers, or evaluate =locals()= and =globals()= in its
stopped frame. Sending a whole buffer executes its top-level
statements. Adding =@final= changes the intended subclassing contract;
adding an attribute annotation can be the appropriate alternative.

**** Strong defaults and project overrides

BasedPyright uses =all= diagnostics as the Emacs-wide default, including
explicit override markers, unannotated attributes, unused call
results, and =Any= checks. A project's =typeCheckingMode= in
=pyrightconfig.json= or =[tool.basedpyright]= in =pyproject.toml= takes
precedence. For example:

#+BEGIN_SRC toml :tangle no
[tool.basedpyright]
typeCheckingMode = "recommended"
reportUnusedCallResult = "none"
#+END_SRC

The namespace adapter sends analysis settings as
=basedpyright.analysis.*=, including workspace diagnostics, auto-import
completion, and extra paths. It retains =python.pythonPath= and
=python.venvPath= for interpreter selection. Upstream Pyright, if used
as a fallback, receives =strict= and its original settings namespace. Do
not confuse an Emacs default with CLI policy: BasedPyright has no
automatically discovered global user configuration file. Commit
project settings when editor and CI must agree, or explicitly supply a
shared config with the CLI's =--project=.

Home Manager provides Ruff's user-wide fallback with all stable rules,
excluding contradictory docstring and formatter-owned style checks. A
project's Ruff configuration replaces that fallback; it is not
implicitly merged. Preview rules and unsafe fix-all remain opt-in. Use
=ruff check --show-settings path/to/file.py= to see the effective
configuration. =ALL= can acquire new rules when Ruff is upgraded.

**** Tool ownership and known overlaps

| Tool             | Responsibility                                            | Important distinction                       |
|------------------+-----------------------------------------------------------+---------------------------------------------|
| BasedPyright     | Types, completion, navigation, rename, type-aware actions | Type suppressions use =pyright: ignore[rule]= |
| Ruff server      | Lint, explicit import sorting, fixes                      | Lint suppressions use =noqa: CODE=            |
| isort then Black | Apheleia save-time formatting and =C-c r=                   | Sorting does not remove unused imports      |
| PET              | Project interpreter and executable selection              | Editor Ruff uses the Nix-built binary       |
| Dape / debugpy   | Runtime frames, scopes, and expressions                   | Requires debugpy in the project environment |

=C-c l r o= sorts imports using Ruff. Use =C-c l a a= for unused-import
fixes or Ruff's safe fix-all. Fix-all can apply other enabled lint
fixes; it is not an import-only command. Ruff's formatting action
remains available through ~C-c l = =~, while normal saves use isort and
Black. Ruff does not read =[tool.black]= or =[tool.isort]=. If a project
customizes those tools, align the equivalent Ruff settings to avoid
alternating changes. Both servers can diagnose an unused import; this
overlap is intentional rather than silently disabling useful checks.

Structural extract/inline refactoring is a separate gap. =pylsp-rope=
can add those actions, but requires another server and describes
support for unsaved documents as experimental. Keep it an explicit
later choice instead of adding competing completion and diagnostics
automatically.

If hints become stuck, first toggle =C-c l T H= off and on. The client
already cancels requests after edits and refreshes on idle/scroll; the
intermittent drift has not yet been reproduced. Record the affected
buffer and action before restarting with =C-c l w r= so it can be
investigated without guessing at timer changes.

**** Configuration

The Python stack deliberately has three small responsibilities:

1. *PET* discovers the correct uv, Poetry, Pipenv, or conventional
   virtual environment before any server starts.
2. *BasedPyright* provides type inference, fuzzy completion, auto
   imports, navigation, rename, occurrence highlighting, inferred-type
   inlays, and type-aware code actions. It is selected through
   =lsp-pyright=, which supports both the upstream server and this more
   capable fork.
3. *Ruff* runs as an additive native language server for lint
   diagnostics, safe fixes, and explicit import organization. The
   installed BasedPyright does not implement import organization,
   despite advertising the action kind, so its organize-import
   capability is disabled.

Apheleia runs isort and then Black asynchronously on save (see [[#uniform-formatter-ui][Uniform
formatter UI]]). The built-in Python shell is project-dedicated, so
several projects can keep independent REPLs. =python-pytest= adds a
transient test dispatcher and =pytest-watcher= supplies the continuous
test loop. Dape uses the =debugpy= installed in the selected project
environment. PET also pre-fills Dape with either the package entry
point or the current file, so starting a Python debugger normally only
requires confirming the suggested command.

On NixOS, PET still supplies the project Python interpreter, but
editor-side Ruff processes use the Nix-built executable from the user
profile. PyPI's Ruff wheel is a generic dynamically linked executable
and exits with code 127 when launched by a graphical Emacs process
without its shell's loader environment.

Pyright and Ruff run in single-root mode so each process sees only its
current project.

=import .first_stage= is invalid Python syntax, independently of uv.
Relative import dots are legal only in a =from= statement. Use either
=from . import first_stage= or, for a particular symbol, =from
.first_stage import my_func=. Completion rewrites a selected sibling
module to the first valid form automatically.

(defun my/python-module-capf ()
  "Complete fuzzy module names and add the selected import."
  (unless (nth 8 (syntax-ppss))
    (let* ((bounds (or (bounds-of-thing-at-point 'symbol)
                       (cons (point) (point))))
           (beginning (car bounds))
           (end (cdr bounds))
           (line-prefix (buffer-substring-no-properties
                         (line-beginning-position) beginning))
           (bare-import (string-match-p
                         "\\`[ \\t]*import[ \\t]+\\'" line-prefix))
           (relative-import (string-match-p
                             "\\`[ \\t]*from[ \\t]+\\.[ \\t]+import[ \\t]+\\'"
                             line-prefix))
           (other-from-import (and (string-match-p
                                    "\\`[ \\t]*from\\_>" line-prefix)
                                   (not relative-import)))
           (member-access (eq (char-before beginning) ?.)))
      ;; BasedPyright owns imported-module members and `from package import'
      ;; symbols. Offering top-level module names there only adds noise.
      (unless (or other-from-import member-access)
        (let* ((siblings (my/python-sibling-modules))
               (candidates (if relative-import
                               siblings
                             (delete-dups
                              (append siblings
                                      (my/python-importable-modules)))))
               (beginning-marker (copy-marker beginning)))
          (list beginning end candidates
                :exclusive 'no
                :company-kind (lambda (_) 'module)
                :exit-function
                (lambda (candidate status)
                  (when (eq status 'finished)
                    (cond
                     ((and bare-import (member candidate siblings))
                      (save-excursion
                        (goto-char beginning-marker)
                        (beginning-of-line)
                        (when (re-search-forward
                               (format "\\_<import[ \\t]+%s\\_>"
                                       (regexp-quote candidate))
                               (line-end-position) t)
                          (replace-match (format "from . import %s" candidate)
                                         t t))))
                     ((not (or bare-import relative-import))
                      (my/python-add-import
                       (if (member candidate siblings)
                           (format "from . import %s" candidate)
                         (format "import %s" candidate)))))))))))))

*** TypeScript and friends

[[https://github.com/typescript-language-server/typescript-language-server][typescript-language-server]] covers type checking, auto imports,
rename, and references. =web-mode= handles mixed HTML / JS / TS
templates (=.jsx=, =.vue=, =.html= with embedded scripts).

File routing:

- =*.ts= opens in =typescript-ts-mode=.
- =*.tsx= opens in =tsx-ts-mode=.
- =*.js= and =*.jsx= open in =web-mode= or =js-ts-mode=.
- HTML below a =templates/= directory, plus =*.jinja=, =*.jinja2=,
  =*.j2=, and =*.djhtml=, opens in =web-mode= with its Jinja engine.
- Other HTML stays in =html-ts-mode= and keeps Prettier on save.

Template buffers disable Apheleia because generic HTML formatters can
rewrite or invalidate embedded template syntax.

#+BEGIN_SRC elisp
(defun my/web-template-file-p ()
  "Return non-nil when the current buffer is a server-rendered template."
  (when-let* ((file buffer-file-name))
    (or (string-match-p "/templates/.*\\.html?\\'" file)
        (string-match-p "\\.\\(?:jinja\\|jinja2\\|j2\\|djhtml\\)\\'" file))))

(defun my/web-template-mode-setup ()
  "Configure Jinja templates without applying a destructive formatter."
  (when (my/web-template-file-p)
    (web-mode-set-engine "jinja")
    (when (bound-and-true-p apheleia-mode)
      (apheleia-mode -1))))

(defconst my/web-template-auto-mode-rules
  '(("/templates/.*\\.html?\\'" . web-mode)
    ("\\.\\(?:jinja\\|jinja2\\|j2\\|djhtml\\)\\'" . web-mode))
  "Auto-mode rules that must take precedence over generic HTML rules.")

(defun my/web-template-prioritize-auto-mode-rules ()
  "Move template rules ahead of generic HTML associations."
  (dolist (rule (reverse my/web-template-auto-mode-rules))
    (setq auto-mode-alist (cons rule (delete rule auto-mode-alist)))))

(my/web-template-prioritize-auto-mode-rules)

;; Loading html-ts-mode prepends its generic \\.html rule, so restore the
;; narrower template rules immediately afterwards.
(with-eval-after-load 'html-ts-mode
  (my/web-template-prioritize-auto-mode-rules))

(use-package web-mode
  :commands web-mode
  :hook (web-mode . lsp-deferred)
  :init
  (add-hook 'web-mode-hook #'my/web-template-mode-setup -10))

(add-to-list 'auto-mode-alist '("\\.ts\\'" . typescript-ts-mode))
(add-to-list 'auto-mode-alist '("\\.tsx\\'" . tsx-ts-mode))

(use-package datastar

*** Terraform and OpenTofu

OpenTofu is the single infrastructure engine. =tofu-ls= uses the
Terraform language-server protocol and provides completion, navigation,
hover, diagnostics, and formatting for =.tf=, =.tfvars=, =.tofu=, and
=.tofutest.hcl= files. =terraform-mode= also invokes =tofu= for its
interactive commands.

Flycheck keeps LSP diagnostics as the primary source. It chains =tflint=
only in projects that contain a =.tflint.hcl= file; this avoids noisy
or project-inappropriate linting elsewhere. Infracost and
=terraform-docs= remain explicit command-line tools rather than Emacs
packages.

#+BEGIN_SRC elisp
(defun my/terraform-flycheck-setup ()
  "Prefer LSP diagnostics and enable TFLint only when configured."
  (setq-local flycheck-disabled-checkers
              (cons 'terraform
                    (when (boundp 'flycheck-disabled-checkers)
                      flycheck-disabled-checkers)))
  (unless (locate-dominating-file default-directory ".tflint.hcl")
    (setq-local flycheck-disabled-checkers
                (cons 'terraform-tflint flycheck-disabled-checkers))))

(use-package terraform-mode
  :mode ("\\.tofutest\\.hcl\\'" . terraform-mode)
  :hook (terraform-mode . lsp-deferred)
  :init
  (add-hook 'terraform-mode-hook #'my/terraform-flycheck-setup -10)
  :custom (terraform-command "tofu"))

(with-eval-after-load 'flycheck
  (setq flycheck-terraform-executable "tofu")
  ;; Flycheck's project validator runs terraform, with no executable
  ;; option (added for flycheck#2360, commit 2a8f8d76), so replace it
  ;; through its public definition API.  A canary in
  ;; tests/diagnostics-test.el fails once upstream stops hard-coding
  ;; terraform; then set that option instead.
  (flycheck-define-project-checker 'terraform-validate
    "An OpenTofu project checker using `tofu validate'."
    :command '("tofu" "validate" "-json")
    :parser #'flycheck-parse-terraform-validate
    :enabled (lambda (directory)
               (directory-files directory nil "\\.tf\\'" t 1))))

(with-eval-after-load 'lsp-terraform
  (setq lsp-terraform-ls-server "tofu-ls"))

(with-eval-after-load 'lsp-diagnostics
  (require 'flycheck)
  (lsp-diagnostics-lsp-checker-if-needed)
  (flycheck-add-next-checker 'lsp '(warning . terraform-tflint) 'append))

*** Java

Two packages cooperate:

- [[https://github.com/emacs-lsp/lsp-java][lsp-java]] wraps the [[https://github.com/eclipse-jdtls/eclipse.jdt.ls][Eclipse JDT Language Server]] (JDTLS), the
  same engine that powers IntelliJ's LSP export and VS Code's Java
  extension. It surfaces the JDTLS option surface as documented
  =lsp-java-*= variables and integrates with =lsp-treemacs= for the
  project view. Features: go to definition (including decompiled
  jars), references, rename, code actions, inlay hints, organise
  imports, run main / test.

- [[https://github.com/svaante/dape][dape]] runs the Debug Adapter Protocol directly. For JDTLS it uses
  the =java-debug= bundle, which =local.el= names in =lsp-java-bundles=
  on a machine that has it.

*System prerequisites*

JDTLS and =lombok.jar= are provisioned by the Nix profile. When a
=jdtls= launcher is on =PATH=, lsp-java runs it instead of downloading
a server of its own, until =M-x lsp-update-servers= installs one: that
server then runs until its directory is deleted.  The installation's =plugins/= is looked for
beside =bin/=, under =share/java/jdtls/= (Nix) and under =libexec/=;
only the Nix layout is checked on a real installation. JDTLS autodiscovers JDK
sources at =$JAVA_HOME/src.zip=, so =JAVA_HOME= must point at a full
JDK rather than a JRE.

The first Java buffer of a session starts JDTLS: =lsp-deferred= loads
lsp-mode, which loads lsp-java with its other clients.

#+BEGIN_SRC zsh :tangle no
ls "$JAVA_HOME/src.zip"
#+END_SRC

(use-package lsp-java
  ;; Without the java grammar, java-mode runs: see
  ;; `my/treesit-remap-when-ready'.
  :hook (java-ts-mode . lsp-deferred)
  :custom
  ;; Google Java Style: 2 space indent.
  (java-ts-indent-offset 2)
  (lsp-java-format-settings-url
   "https://raw.githubusercontent.com/google/styleguide/gh-pages/eclipse-java-google-style.xml")
  (lsp-java-format-settings-profile "GoogleStyle")
  (lsp-java-format-enabled t)
  (lsp-java-maven-download-sources t)
  (lsp-java-references-code-lens-enabled t)
  (lsp-java-implementations-code-lens-enabled t)
  (lsp-java-signature-help-enabled t)
  ;; Decompile jars without sources via Fernflower.
  (lsp-java-content-provider-preferred "fernflower")
  (lsp-java-import-gradle-enabled t)
  (lsp-java-autobuild-enabled t)
  (lsp-java-vmargs
   '("--add-modules=ALL-SYSTEM"
     "--add-opens" "java.base/java.util=ALL-UNNAMED"
     "--add-opens" "java.base/java.lang=ALL-UNNAMED"))
  :config
  ;; Run the jdtls launcher on PATH.  lsp-java tells that a server is
  ;; installed from the launcher jar under `lsp-java-server-install-dir',
  ;; a directory it deletes when it installs a server: give it one of its
  ;; own, whose plugins/ links to the installation's.
  (when-let* ((jdtls (executable-find "jdtls"))
              (home (file-name-directory
                     (directory-file-name
                      (file-name-directory (file-truename jdtls)))))
              (plugins (seq-find #'file-directory-p
                                 (mapcar (lambda (path) (expand-file-name path home))
                                         '("plugins" "share/java/jdtls/plugins"
                                           "libexec/plugins"))))
              (install (no-littering-expand-var-file-name "lsp-java/jdtls-on-path/"))
              (link (expand-file-name "plugins" install)))
    (make-directory install t)
    (setq lsp-java-server-install-dir install)
    ;; `lsp-update-servers' installs a server there, plugins/ included:
    ;; keep it until the user deletes it.
    (if (and (file-directory-p link) (not (file-symlink-p link)))
        (message "lsp-java runs the server installed in %s; delete it to run %s"
                 install jdtls)
      (make-symbolic-link plugins link t)
      (setq lsp-java-jdt-ls-prefer-native-command t
            lsp-java-jdt-ls-command jdtls))))

*** Nix

=nix-mode= for =.nix= files. =nixd= is the language server (ensure it
is on =PATH=, e.g. via =home/base.nix=).  On a NixOS machine,
=local.el= names the machine's flake in =my/nixd-flake=, and its
=nixosConfigurations= entry in =my/nixd-flake-host= when that is not
the host name.  nixd then completes and documents every =services.…=
and =programs.…= option of that system and of the login user's Home
Manager configuration.

=alejandra= formats on save via apheleia (see *Formatting*).  =C-c n r=
opens a =nix repl= session for interactive introspection.

=nix-prettify-global-mode= shortens =/nix/store/<hash>-…= paths to
=/nix/store/…-…= in every buffer (compilation, eshell, messages),
reducing visual noise.

| Binding   | Command            | Purpose                       |
|-----------+--------------------+-------------------------------|
| =C-c n r= | =nix-repl=         | Open interactive =nix repl=   |
| =C-c n b= | =nix-build=        | Run =nix build= (compilation) |
| =C-c n u= | =nix-shell-unpack= | Fetch & unpack derivation src |
| =C-c n s= | =nix-shell=        | Open a =nix-shell= buffer     |

#+BEGIN_SRC elisp
(use-package nix-mode
  :hook (nix-mode . lsp-deferred)
  :bind (:map nix-mode-map
         ("C-c n r" . nix-repl)

* Spelling and language checking

Three layers work together:

1. =jinx= — fast multilingual spell checker using libenchant → hunspell.
   Checks all active languages simultaneously with minimal overhead
   (only visible text is processed).
2. =ltex-ls-plus= via the standalone =lsp-ltex-plus= client covers
   LanguageTool grammar rules for English, French, Polish, Spanish, and
   more. Its findings show through Flycheck, next to those of the
   buffer's other checkers.
3. =flycheck-grammalecte= adds deep French grammar analysis
   (Grammalecte is more thorough than LanguageTool on French gender
   agreement, conjugation, and typography). Active only in prose
   buffers so =lsp-mode='s diagnostics flow in prog-mode is
   undisturbed.

Chinese (Simplified and Traditional) is handled differently: ideographic
writing has no conventional spell checker. We provide a Pinyin input
method (=pyim=), correct CJK/Latin spacing (=pangu-spacing=), and extend
the font fallback chain with Noto Sans CJK.

[[file:docs/reference/dependencies.org][External dependencies]] lists the programs and dictionaries these
need, with their nixpkgs attributes.  On macOS, copy the hunspell
dictionaries' =.dic= and =.aff= files to =~/Library/Spelling/=.


** Multilingual spell checking (jinx)

=jinx= uses libenchant as an abstraction layer over installed
hunspell/aspell dictionaries. All active languages are checked at
once — just one package replaces =flyspell=, =flyspell-correct=, and
=guess-language=. Change languages interactively with =C-M-$=, or set

  :custom
  ;; Space-separated enchant locale codes checked simultaneously.
  ;; Latin uses aspell-la; Chinese has no hunspell dict (handled below).

** Grammar checking via LTeX language server
:PROPERTIES:
:CUSTOM_ID: grammar-checking
:END:

=ltex-ls-plus= wraps LanguageTool as a local server. The standalone
[[https://github.com/ltex-plus/emacs-ltex-plus][lsp-ltex-plus client]] talks to it through Emacs JSON-RPC, independently
of =lsp-mode=. Preserve the previous prose modes, automatic language
detection, French mother-tongue rules and informational severity.
Jinx continues to provide spelling checks when language detection is
=auto=. Use =M-x lsp-ltex-plus-change-language= to select a language.

Grammar findings show through Flycheck, like every other checker's.
Flycheck runs one checker per buffer, the one the buffer selects, then
the chain of its next checkers; LTeX+ and =lsp-mode= each select their
own.  =my/flycheck-chain-prose-checkers= links LTeX+ after =lsp-mode=,
then Org lint and Grammalecte after LTeX+.  Where =lsp-mode= serves a
buffer its checker stays selected, even when LTeX+ restarts, so
Markdown keeps =marksman='s findings, Org keeps Org lint's, and French
prose gets Grammalecte's.  A
server that publishes during a check is shown by one more check after
it.  List them with =C-c ! l=, and run =M-x
lsp-ltex-plus-doctor= to verify the server.  Markdown keeps =marksman=
for cross-link navigation; LaTeX starts Texlab from its own section.
Fileless buffers and comint input are excluded to avoid extending the
old activation scope.

#+BEGIN_SRC elisp
(defun my/flycheck-chain-prose-checkers ()
  "Chain the defined prose checkers after the checker a buffer selects.
LTeX+ and lsp-mode each select their checker for a buffer, and
Flycheck runs only the selected checker, then the chain of its next
checkers.  Link LTeX+ and Grammalecte after lsp-mode, then org-lint
and Grammalecte after LTeX+, then Grammalecte after org-lint, so each
reports whichever checker the buffer selects.  A checker is defined
when its package first needs it, so run again each time one is;
linking again changes nothing."
  (when (flycheck-valid-checker-p 'lsp-ltex-plus)
    ;; Flycheck runs a next checker only if it is registered.
    (add-to-list 'flycheck-checkers 'lsp-ltex-plus t))
  (pcase-dolist (`(,checker . ,next)
                 '((lsp . lsp-ltex-plus) (lsp . grammalecte)
                   (lsp-ltex-plus . org-lint) (lsp-ltex-plus . grammalecte)
                   (org-lint . grammalecte)))
    (when (and (flycheck-valid-checker-p checker)
               (flycheck-valid-checker-p next))
      (flycheck-add-next-checker checker (cons t next) t))))

(defun my/flycheck-check-again ()
  "Check the buffer once more, now that its check has finished.
One-shot, on the buffer's `flycheck-after-syntax-check-hook'."
  (remove-hook 'flycheck-after-syntax-check-hook #'my/flycheck-check-again t)
  (flycheck-buffer))

(defun my/flycheck-check-again-after-lsp-publish ()
  "Check lsp-mode's buffers again once their running check has finished.
On `lsp-diagnostics-updated-hook'.  lsp-mode asks Flycheck to check
its buffers when a server publishes, and Flycheck ignores the request
while a check runs.  A check that chains Grammalecte after lsp-mode
runs for a while; a publish meanwhile, such as marksman's broken
link, would otherwise show only at the next check.  Only the shown
buffers of the publishing server, which lsp-mode's own request is
limited to: another server's publishes must not check them again."
  (dolist (buffer (buffer-list))
    (with-current-buffer buffer
      (when (and (get-buffer-window buffer)
                 (bound-and-true-p lsp-diagnostics-mode)
                 (memq lsp--cur-workspace lsp--buffer-workspaces)
                 (bound-and-true-p flycheck-mode)
                 (flycheck-running-p))
        (add-hook 'flycheck-after-syntax-check-hook
                  #'my/flycheck-check-again nil t)))))

(defun my/flycheck-select-lsp-over-ltex-plus ()
  "Select lsp-mode's checker again where LTeX+ has just taken its place.
On `lsp-ltex-plus-mode-hook'.  Turning LTeX+ on selects its checker,
as after `lsp-ltex-plus-restart-server'.  Where lsp-mode serves the
buffer, its checker must stay selected: it chains LTeX+'s, and nothing
chains it back."
  (when (and (bound-and-true-p lsp-diagnostics-mode)
             (eq flycheck-checker 'lsp-ltex-plus))
    (setq flycheck-checker 'lsp)))

;; lsp-mode defines its checker in the first buffer it serves; link it
;; at once, before that buffer's first check.
(with-eval-after-load 'lsp-diagnostics
  (require 'flycheck)
  (lsp-diagnostics-lsp-checker-if-needed)
  (my/flycheck-chain-prose-checkers)
  (add-hook 'lsp-diagnostics-updated-hook
            #'my/flycheck-check-again-after-lsp-publish))

(use-package lsp-ltex-plus
  :straight (lsp-ltex-plus :type git :host github
                          :repo "ltex-plus/emacs-ltex-plus")
  ;; Its checker is defined when the first buffer attaches to it.
  :hook ((lsp-ltex-plus-mode . my/flycheck-chain-prose-checkers)
         (lsp-ltex-plus-mode . my/flycheck-select-lsp-over-ltex-plus))
  :init
  ;; This client owns its JSON-RPC connection; keep legacy LTeX clients off.
  (with-eval-after-load 'lsp-mode

    (add-to-list 'lsp-disabled-clients 'ltex-ls))
  (lsp-ltex-plus-enable-for-modes
   :restrict-to '(text-mode bibtex-mode context-mode latex-mode LaTeX-mode
                 markdown-mode gfm-mode org-mode rst-mode))
  ;; Keep marksman when removing the old broad text-mode hook.  LaTeX
  ;; starts Texlab from its own section; no server serves BibTeX.
  (add-hook 'markdown-mode-hook #'lsp-deferred)
  :custom
  (lsp-ltex-plus-language "auto")
  (lsp-ltex-plus-additional-rules-mother-tongue "fr")
  (lsp-ltex-plus-diagnostic-severity "information")
  (lsp-ltex-plus-diagnostics-provider 'flycheck)
  (lsp-ltex-plus-check-fileless-buffers nil)

** French grammar: Grammalecte

[[https://grammalecte.net][Grammalecte]] provides French-specialist rules — gender agreement,
conjugation, false friends, typography — beyond what LanguageTool covers.
It integrates via a =flycheck= backend.  It uses the Grammalecte
Python package installed beside =grammalecte-cli.py= on =PATH=, under
=../lib/python*/site-packages=, as the Nix package =grammalecte=, a
virtual environment or a =pip= prefix lay it out; without one, the
checker stays off.  The package is looked up again once
exec-path-from-shell has set =PATH=.  It never checks for a newer
version, even from =M-x grammalecte-conjugate-verb=; do not run
=M-x grammalecte-download-grammalecte=, which would try to replace the
package (it fails on the link to it).

Grammalecte checks only buffers that declare French: an Org buffer
with =#+LANGUAGE: fr=, or a file whose local =jinx-languages= starts
with French, such as =-*- jinx-languages: "fr_FR" -*-=.  Its French
typography rules would flag every colon and straight quote of an
English text.  =C-c ! g= applies its first suggestion at point; its
right-click menu is not bound, so =<mouse-3>= keeps
=mouse-save-then-kill= in every Flycheck buffer.

=flycheck= is the one diagnostic front end.  Language servers report
through =lsp-diagnostics-mode= (configured in the LSP section), LTeX+
through its own checker, and in French prose =flycheck-grammalecte=
adds French grammar checks after them.  All share the flycheck
overlays, keys (=C-c ! n/p/l=) and doom-modeline segment.  Flycheck is
on from the end of startup, so a file opened by =emacsclient= or on the
command line is checked at once.  =jinx= continues to handle spell
checking independently.

#+BEGIN_SRC elisp
;; global-flycheck-mode activates flycheck in every buffer that has a
;; suitable checker.  In LSP-managed buffers lsp-diagnostics-mode
;; pipes server diagnostics into flycheck (see the LSP section).
;; flycheck-grammalecte adds French grammar checks in French prose.
(use-package flycheck
  ;; At the end of startup, before the first file: an idle timer would
  ;; leave a file opened first unchecked until Emacs is idle.
  :hook (after-init . global-flycheck-mode)
  :bind (("C-c ! n" . flycheck-next-error)
         ("C-c ! p" . flycheck-previous-error)
         ("C-c ! l" . flycheck-list-errors)
         ("C-c ! v" . flycheck-verify-setup))
  :custom
  ;; Raise the error threshold for large generated files (e.g. minified
  ;; JS or huge Python modules) so flycheck doesn't give up early.
  (flycheck-checker-error-threshold 10000)
  :config
  (with-eval-after-load 'which-key
    (which-key-add-key-based-replacements "C-c !" "flycheck")))

(defun my/grammalecte-french-buffer-p ()
  "Return non-nil when the current buffer declares French as its language.
Org's #+LANGUAGE: fr keyword, or a buffer-local `jinx-languages' that
starts with French, as a file-local variable sets it."
  (or (and (derived-mode-p 'org-mode)
           (equal (cadar (org-collect-keywords '("LANGUAGE"))) "fr"))
      (and (local-variable-p 'jinx-languages)
           (string-prefix-p "fr" jinx-languages))))

(defun my/grammalecte-use-system-package ()
  "Use the Python package of the Grammalecte on `exec-path', if any.
The package lies beside grammalecte-cli.py, rather than in a copy
downloaded into flycheck-grammalecte.  flycheck-grammalecte puts the
parent of `grammalecte-python-package-directory' on PYTHONPATH for
every Python process Emacs starts, so that directory is a private link
to the package: its own site-packages would put a virtual
environment's or pip's other packages ahead of a project's.  Run when
the package loads, and again once exec-path-from-shell has set
`exec-path': a GUI Emacs started from the macOS Dock lacks the
profile's directory before.  On a change, Flycheck asks again whether
Grammalecte is installed in the buffers Grammalecte could check."
  (when-let* ((cli (executable-find "grammalecte-cli.py"))
              (package (car (file-expand-wildcards
                             (expand-file-name
                              "../lib/python*/site-packages/grammalecte"
                              (file-name-directory (file-truename cli))))))
              (link (no-littering-expand-var-file-name "grammalecte/grammalecte")))
    (unless (and (equal grammalecte-python-package-directory link)
                 (equal (file-symlink-p link) package))
      (make-directory (file-name-directory link) t)
      (make-symbolic-link package link t)
      (setq grammalecte-python-package-directory link)
      (dolist (buffer (buffer-list))
        (with-current-buffer buffer
          (when (and (bound-and-true-p flycheck-mode)
                     (flycheck-checker-supports-major-mode-p 'grammalecte))
            (flycheck-reset-enabled-checker 'grammalecte)))))))

(defvar my/grammalecte-version nil
  "The package `grammalecte--version' probed last, and what it returned.")

(defun my/grammalecte-version-once (probe)
  "Return what PROBE, `grammalecte--version', finds, probing once per package.
Flycheck asks it in each prose buffer whether Grammalecte is
installed, before the predicate that limits Grammalecte to French;
each probe runs python3 and blocks Emacs for about 0.1 s."
  (let ((package (file-truename grammalecte-python-package-directory)))
    (unless (equal (car my/grammalecte-version) package)
      (setq my/grammalecte-version (cons package (funcall probe))))
    (cdr my/grammalecte-version)))

;; Insert correct whitespace between CJK and Latin/ASCII characters.
;; "Hello世界" becomes "Hello 世界" on save.
;;
;; pangu-spacing-mode unconditionally registers a jit-lock callback that
;; runs a CJK/Latin boundary regex on every fontification pass.  For
;; pure-ASCII buffers (the vast majority) this is wasted work.  The
;; guard below activates the mode only when >= 5% of the buffer is CJK,
;; and installs a cheap after-change-functions hook to lazily activate
;; it if CJK text is later inserted.

(defun my/buffer-cjk-fraction ()
  "Return the fraction of buffer characters that are CJK.
Uses Emacs character categories: \\cC (two-byte Chinese), \\cj (Japanese),
\\ck (Korean)."
  (if (= (point-min) (point-max))
      0.0
    (let ((cjk-count (how-many "\\cC\\|\\cj\\|\\ck" (point-min) (point-max))))
      (/ (float cjk-count) (- (point-max) (point-min))))))

(defun my/maybe-enable-pangu-spacing ()
  "Enable `pangu-spacing-mode' only when >= 5% of buffer content is CJK.
Also installs a self-removing `after-change-functions' hook so that if CJK
text is later inserted into a buffer that was initially below the threshold,
the mode activates lazily."
  (if (>= (my/buffer-cjk-fraction) 0.05)
      (pangu-spacing-mode 1)
    (add-hook 'after-change-functions
              #'my/pangu-spacing-lazy-activate nil t)))

(defun my/pangu-spacing-lazy-activate (beg end _len)
  "Activate pangu-spacing if CJK text was inserted into this buffer."
  (when (save-excursion
          (goto-char beg)
          (re-search-forward "\\cC\\|\\cj\\|\\ck" end t))
    (pangu-spacing-mode 1)
    (remove-hook 'after-change-functions
                 #'my/pangu-spacing-lazy-activate t)))

(use-package pangu-spacing
  :hook (text-mode . my/maybe-enable-pangu-spacing)
  :custom
  ;; Write real spaces to the file rather than display-only overlays.
  ;; The actual insertion happens on save (write-file-hooks), not on
  ;; every keystroke; jit-lock only maintains display overlays.
  (pangu-spacing-real-insert-separtor t))

Three terminal emulators coexist.  Each has strengths; pick the one
that fits the task:

| Terminal | Invocation        | Sweet spot                                    | Multi-line                | Limitations                                                                                                        |
|----------+-------------------+-----------------------------------------------+---------------------------+--------------------------------------------------------------------------------------------------------------------|
| =eat=    | =M-x eat-project= | Daily terminal: fast, full-screen apps        | =C-x C-e= (edit in Emacs) | Emacs keys in its scrollback after =C-c C-e=; Emacs stalls under bulk output                                       |
| =mistty= | =C-c t= / =C-c T= | Emacs-native prompt editing (kill-ring, undo) | =C-j= (in-place newline)  | Slow under bulk output; opens in a second window; starts in the buffer's directory, not the project root           |
| =gterm=  | =M-x gterm=       | Ghostty VT engine, best Unicode, TUI apps     | =C-x C-e= (edit in Emacs) | Early prototype; no mouse; needs Zig; no scrollback search; starts in the buffer's directory, not the project root |

The parity matrix of plan 091 checks the same capabilities in the
three (=tests/scenarios/l3-pty-*.el=): opening at the project root,
directory tracking, the fzf keys =C-r=, =C-t= and =M-c=, word motion
and deletion, =C-x C-e=, multi-line commands, a full-screen program,
searching and copying the scrollback, and resizing.  The limitations
above are its known gaps.  Whether Emacs stays responsive under bulk
output is an opt-in timing check, for an idle machine: gterm passes it
(=PTY_MATRIX_TIMING=1=); eat with its default latencies and mistty
fail it, a known gap (=PTY_MATRIX_GAPS=1=).

For a GUI terminal, use [[https://ghostty.org/][Ghostty]] on macOS.

=hl-line-mode= is disabled in all terminal buffers (mistty, gterm) to
avoid visual noise over the terminal output.

Full-screen alternate-screen programs (btop, htop, opencode) render
correctly in gterm.  =M-x my/btop= opens a gterm buffer running btop:

#+BEGIN_SRC elisp
(defun my/btop ()
  "Open a gterm buffer running btop."
  (interactive)
  (let ((buf-name "*gterm* btop"))
    (if-let* ((buf (get-buffer buf-name)))
        (switch-to-buffer buf)
      (gterm)
      (rename-buffer buf-name)

#+END_SRC

The three terminals bind the same keys to the same shell widgets.
Each key sends what zsh's Emacs keymap expects: the escape sequences
that terminals send for =M-<left>= and =M-<right>= are unbound there,
and =C-x= is an Emacs prefix that a terminal never forwards.  The
parity matrix of plan 091 (=tests/scenarios/l3-pty-*.el=) checks them
in each terminal.

*** mistty

See [[https://github.com/szermatt/mistty][supportive documentation]].

=mistty= is a thin wrapper over =term.el=.  It renders the terminal zone
through the shell itself, so shell completion, syntax highlighting, and
multi-line editing work natively.  Global keys: =C-c t= / =C-c T=.

Full-screen alternate-screen programs (btop, htop, opencode) run in
mistty's fullscreen mode, in the window mistty opened in, which is
half the frame: =C-x 1= first gives them room.  Bulk output, such as
=seq 1 200000=, keeps Emacs slow to answer for its duration; mistty's
built-in backend, =term.el=, renders it in Lisp.

#+BEGIN_SRC elisp
(use-package mistty
  :straight (:host github :repo "szermatt/mistty")
  :bind (("C-c t" . mistty)
         ("C-c T" . mistty-other-window)
         :map mistty-prompt-map
         ;; RET runs the command; C-j inserts a newline for multi-line editing.
         ("RET"        . mistty-send-command)
         ("C-j"        . mistty-newline)
         ;; Forward fzf keys to the shell (C-r history, C-t file, M-c cd).
         ;; Shadows isearch-backward, transpose-chars, capitalize-word
         ;; in the prompt zone; acceptable trade-off at a shell prompt.
         ("C-r"       . mistty-send-key)
         ("C-t"       . mistty-send-key)
         ("M-c"       . mistty-send-key)
         ;; zsh's edit-command-line widget.  `mistty-send-key' fails on
         ;; a sequence of two keys.
         ("C-x C-e"   . my/terminal-edit-command-line)
         ;; Pass navigation keys to the shell rather than Emacs.
         ("M-r"       . mistty-send-key)
         ("M-s"       . mistty-send-key)
         ;; Word motion as zsh binds it, ESC b and ESC f.
         ;; `mistty-send-key' would send the xterm codes \e[1;3D and
         ;; \e[1;3C, which zsh leaves unbound.
         ("M-<left>"  . my/terminal-backward-word)
         ("M-<right>" . my/terminal-forward-word)
         ;; M-<up> / M-<down> are intentionally NOT overridden here.
         ;; The default mistty-mode-map already binds them to
         ;; mistty-send-C-p / mistty-send-C-n, which send C-p / C-n
         ;; (readline previous/next history).  Binding them to
         ;; mistty-send-key would send xterm escape codes (\e[1;3A)
         ;; that most shells don't understand, producing literal ";3A".
         ))
#+END_SRC

Key bindings:
- =C-c t= / =C-c T=: open mistty buffer / in other window
- The purple margin marks the terminal zone; Emacs editing commands
  (=M-b=, =M-f=, =C-k=, etc.) work there and are replayed to the shell
- =RET=: send the command (run it)
- =C-j=: insert a newline (compose multi-line commands)
- =C-r= / =C-t= / =M-c=: fzf history, file, and cd widgets (forwarded to shell)
- =C-x C-e=: open current command in =$EDITOR= (zsh =edit-command-line=)
- =M-up= / =M-down=: previous/next history (uses C-p/C-n via the default binding)
- =M-left= / =M-right=: backward-word / forward-word (sends ESC+b / ESC+f)
- =C-c C-q=: raw key passthrough (for programs needing low-level input)

Completion notes:
- *Shell-native TAB*: pressing =TAB= sends the keystroke to the shell
  process, so zsh's own completion system works out of the box
  (commands, paths, options, etc.).
- *Emacs file-path completion*: =cape-file= is registered globally in
  =completion-at-point-functions=, so corfu can offer file-path
  completions anywhere, including mistty buffers.  Trigger with =M-TAB=
  or wait for corfu's auto-complete.
- *Shellcheck*: live lint is not feasible inside a terminal emulator
  because there is no file-backed buffer.  Use =zsh-syntax-highlighting=
  in your shell for real-time feedback.  When editing =.sh= / =.bash= /
  =.zsh= script files, =bash-language-server= reports shellcheck's
  findings through Flycheck in both =sh-mode= and =bash-ts-mode=.

*** gterm (experimental)

See [[https://github.com/rwc9u/emacs-libgterm][supportive documentation]].

=gterm= is a terminal emulator built on [[https://ghostty.org/][Ghostty]]'s VT engine
(libghostty-vt) via a Zig dynamic module.  It offers SIMD-optimised
escape-sequence parsing, better Unicode/grapheme-cluster support, and
text reflow on resize.  Use =M-x gterm= to open a buffer.  Its buffer
holds the visible screen only: output scrolled out of view is reached
by paging (=S-<prior>=), not by searching.  The configuration answers
the cursor position queries of fzf and follows the directory the
shell reports, which gterm itself ignores.

*Status*: early prototype.  No mouse support yet; some character-width
mismatches with Powerline/NerdFont glyphs.  Requires Zig ≥ 0.15.2 at
compile time.  The module is built once, on request, with =M-x
my/gterm-compile-module=, which clones Ghostty when it is missing;
until then =M-x gterm= says so instead of building it (completing a
=gterm-= name in =C-h f= or =C-h v= still loads gterm.el, which offers
to build).  Must be built with =-Doptimize=ReleaseSafe= because Zig's
debug allocator guard pages trigger Emacs's =SIGSEGV= handler.  The
command runs upstream's =gterm-module-compile=, whose =zig build= has
no =-Doptimize=, and loads that Debug module into the session.  So
for now, after it, rebuild by hand with =zig build
-Doptimize=ReleaseSafe= in =gterm-source-dir=, then restart Emacs: a
loaded module cannot be unloaded.  On macOS 26 that hand build needs
the SDK shim below, which only wraps =gterm-module-compile=.

*macOS 26 workaround*: The macOS 26 (Tahoe) SDK dropped =arm64-macos=
stubs from its =.tbd= files, providing only =arm64e-macos=.  Zig 0.15
targets =arm64-macos= so its internal linker cannot resolve libc
symbols against the macOS 26 SDK.  The workaround below detects this
situation and creates a temporary =xcrun= shim that redirects Zig to
the newest macOS 15.x SDK (which still has =arm64-macos= stubs).  The
shim is scoped to the compilation process only and does not affect the
rest of the system.

#+BEGIN_SRC elisp
(use-package gterm
  :straight (:host github :repo "rwc9u/emacs-libgterm" :files ("*"))
  :init
  ;; Point source-dir at the repos checkout so zig build finds
  ;; vendor/ghostty and the existing zig-out artefacts.  The
  ;; straight/build/ copy lacks a working emacs-module.h detection on
  ;; NixOS because the Zig-side fallback is a macOS path.  The
  ;; checkout is under `straight-base-dir', which is not always
  ;; `user-emacs-directory': test sessions have their own.
  (setq gterm-source-dir (expand-file-name "straight/repos/emacs-libgterm/"
                                           straight-base-dir)
        gterm-module-path (expand-file-name
                           (concat "zig-out/lib/libgterm-module" module-file-suffix)
                           gterm-source-dir)
        ;; /bin/zsh does not exist on NixOS; find zsh via PATH.
        gterm-shell (or (executable-find "zsh") (getenv "SHELL") "/bin/sh"))

  ;; Loading gterm.el without its module builds it, after cloning
  ;; Ghostty, or asks to, before any advice on `gterm' could run: the
  ;; autoload of `gterm' loads gterm.el first.  So `gterm' stands in
  ;; for that autoload, and the module is built on request only.
  (defun my/gterm-compile-module ()
    "Build gterm's Zig module, cloning Ghostty when missing, then load gterm.
Run it once after installing gterm: `gterm' refuses to start until
the module exists.  It builds and loads a Debug module; rebuild it
with zig build -Doptimize=ReleaseSafe in `gterm-source-dir', then
restart Emacs."
    (interactive)
    ;; `dlet': gterm.el reads it while it loads; a lexical `let' fails.
    (dlet ((gterm-always-compile-module t))
      (require 'gterm)))

  (unless (featurep 'gterm)
    (defalias 'gterm
      (lambda ()
        "Create a new gterm terminal buffer, once gterm's module is built.
Without the module, signal a `user-error' that names
`my/gterm-compile-module', and leave gterm.el unloaded: loading it
would build the module.  gterm.el replaces this stand-in for its
autoload with the real `gterm' when it loads.  Completing a gterm-
name in C-h f or C-h v still loads gterm.el."
        (interactive)
        (unless (file-exists-p gterm-module-path)
          (user-error "gterm: no module at %s; build it with M-x my/gterm-compile-module"
                      gterm-module-path))
        (require 'gterm)
        (call-interactively #'gterm))))

  ;; macOS 26 SDK workaround: the default SDK (MacOSX.sdk) may lack
  ;; arm64-macos stubs (only arm64e-macos), breaking Zig's linker.
  ;; Detect this at compile time and shim xcrun to return a macOS 15
  ;; SDK that still ships arm64-macos stubs.  None of it is defined
  ;; elsewhere than on macOS.
  (when my/macos-p
    (defun my/gterm--macos15-sdk-path ()
      "Return the newest macOS 15.x SDK path, or nil if none found."
      (let ((sdk-dir "/Library/Developer/CommandLineTools/SDKs/"))
        (when (file-directory-p sdk-dir)
          (car (last (sort (file-expand-wildcards
                            (concat sdk-dir "MacOSX15*.sdk"))
                           #'string<))))))

    (defun my/gterm--sdk-needs-workaround-p ()
      "Return non-nil if the default macOS SDK lacks arm64-macos stubs."
      (let ((default-tbd
             (expand-file-name
              "usr/lib/libSystem.tbd"
              "/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk")))
        (and (file-exists-p default-tbd)
             (with-temp-buffer
               (insert-file-contents default-tbd nil 0 500)
               (not (string-match-p "arm64-macos" (buffer-string)))))))

    (defun my/gterm-compile-with-sdk-workaround (orig-fn &rest args)
      "Advice around `gterm-module-compile' to shim xcrun on macOS 26+.
Creates a temporary xcrun wrapper that returns a macOS 15.x SDK path,
prepends it to PATH, and cleans up afterwards."
      (if-let* (((my/gterm--sdk-needs-workaround-p))
                (sdk (my/gterm--macos15-sdk-path))
                (shim-dir (make-temp-file "gterm-xcrun-" t)))
          (let ((shim-file (expand-file-name "xcrun" shim-dir)))
            (with-temp-file shim-file
              ;; Zig calls `xcrun --sdk macosx --show-sdk-path`.  Redirect
              ;; only macOS SDK queries; let other SDK types (iphoneos etc.)
              ;; fall through to the real xcrun.
              (insert "#!/bin/sh\n"
                      "case \"$*\" in\n"
                      "  *macosx*--show-sdk-path*|*--show-sdk-path*macosx*)\n"
                      "    echo '" sdk "' ;;\n"
                      "  *) exec /usr/bin/xcrun \"$@\" ;;\n"
                      "esac\n"))
            (set-file-modes shim-file #o755)
            (let ((process-environment
                   (cons (concat "PATH=" shim-dir ":" (getenv "PATH"))
                         process-environment)))
              (unwind-protect
                  (apply orig-fn args)
                (delete-directory shim-dir t))))
        (apply orig-fn args)))

    (advice-add 'gterm-module-compile :around
                #'my/gterm-compile-with-sdk-workaround))
  :config
  ;; Upstream bug: `gterm-mode-map' binds (vector 'control c), a
  ;; two-event sequence [control <char>], instead of the event C-<char>,
  ;; so every Ctrl+letter from its loop is dead.  It regressed in
  ;; https://github.com/rwc9u/emacs-libgterm/pull/5 (56c0c69), which
  ;; replaced the working (vector (list 'control c)).  Rebind them; the canary scenario of
  ;; tests/scenarios/l3-pty-gterm.el fails once upstream binds the
  ;; events correctly, and this loop can go.  Exclude letters with
  ;; dedicated bindings: C-c (prefix), C-g (quit), C-h (help), C-i/TAB,
  ;; C-m/RET, C-q (send-next-key), C-x (prefix), C-y (yank).
  (cl-loop for c from ?a to ?z
           unless (memq c '(?c ?g ?h ?i ?m ?q ?x ?y))
           do (define-key gterm-mode-map
                          (kbd (format "C-%c" c))
                          #'gterm-send-ctrl-key))
  ;; Meta+letter: send ESC + letter for word navigation and fzf cd.
  ;; M-f/M-b (word nav), M-d (kill-word), M-c (fzf cd widget).
  (dolist (c '(?b ?c ?d ?f))
    (define-key gterm-mode-map (kbd (format "M-%c" c)) #'my/terminal-send-meta-key))
  ;; Word keys as in eat and mistty; upstream sends the xterm codes
  ;; \e[1;3D and \e[1;3C for M-<left> and M-<right>, which zsh leaves
  ;; unbound, and ^H for C-<backspace>.
  (define-key gterm-mode-map (kbd "M-DEL") #'my/terminal-backward-kill-word)
  (define-key gterm-mode-map (kbd "C-<backspace>") #'my/terminal-backward-kill-word)
  (define-key gterm-mode-map (kbd "M-<left>") #'my/terminal-backward-word)
  (define-key gterm-mode-map (kbd "M-<right>") #'my/terminal-forward-word)
  (define-key gterm-mode-map (kbd "<backtab>") #'my/terminal-send-backtab)
  ;; zsh's edit-command-line: C-x C-e as in eat and mistty, and C-c C-e.
  (define-key gterm-mode-map (kbd "C-x C-e") #'my/terminal-edit-command-line)
  (define-key gterm-mode-map (kbd "C-c C-e") #'my/terminal-edit-command-line)

  ;; gterm's module reads the shell's output but never answers a
  ;; terminal query, and ignores OSC 7.  These run after
  ;; `gterm--filter' has fed OUTPUT to the module.  A sequence split
  ;; across two reads is missed; both are short and written at once.
  ;; Upstream issues, drafted in plan 091, not yet filed at
  ;; https://github.com/rwc9u/emacs-libgterm: "No reply to CSI 6 n"
  ;; and "OSC 7 is ignored".  Expiry: the CPR cell of
  ;; tests/scenarios/l3-pty-gterm.el fails on a second reply once
  ;; upstream answers; then drop `my/gterm-report-cursor'.  Once
  ;; upstream's filter sets `default-directory' on OSC 7, check with
  ;; this advice removed that the cd cell still passes, then drop it.
  (defun my/gterm-report-cursor (process output)
    "Answer a cursor position query, CSI 6 n, in OUTPUT of gterm's PROCESS.
fzf asks where the cursor is before it draws its list below the
prompt, and waits for the answer.  Advice after `gterm--filter'."
    (when (and (string-search "\e[6n" output)
               (buffer-live-p (process-buffer process)))
      (pcase-let ((`(,row . ,column) (gterm-cursor-pos
                                      (buffer-local-value 'gterm--term
                                                          (process-buffer process)))))
        (process-send-string process (format "\e[%d;%dR" (1+ row) (1+ column))))))

  (defun my/gterm-track-directory (process output)
    "Follow the directories the shell reports with OSC 7 in OUTPUT of PROCESS.
Set the `default-directory' of gterm's PROCESS buffer to the path of
the last report, if it is a local directory here.  Unlike eat and mistty,
it ignores the host and takes the path as sent, not percent-decoded,
as the shell hook of the Host ZSH setup sends it.  Advice after
`gterm--filter'."
    (let ((start 0)
          (directory nil))
      (while (string-match (rx "\e]7;file://" (* (not (any "/")))
                               (group "/" (* (not (any "\a\e"))))
                               (or "\a" "\e\\"))
                           output start)
        (setq directory (decode-coding-string (match-string 1 output) 'utf-8)
              start (match-end 0)))
      ;; Any program can print a report: a remote path would make
      ;; `file-directory-p' open a TRAMP connection from this filter.
      (when (and directory (not (file-remote-p directory))
                 (file-directory-p directory)
                 (buffer-live-p (process-buffer process)))
        (with-current-buffer (process-buffer process)
          (setq default-directory (file-name-as-directory directory))))))

  (advice-add 'gterm--filter :after #'my/gterm-report-cursor)
  (advice-add 'gterm--filter :after #'my/gterm-track-directory))
#+END_SRC

** Emacs MCP

Provide Emacs with an MCP (Model Context Protocol) server. The MCP
server exposes Emacs tools (buffer operations, file access,
evaluation) to agents that can read and modify code directly within
the editor. The server listens on the local
=~/.emacs.d/var/mcp-server/emacs-mcp-server.sock= Unix socket.  It
starts once Emacs has been idle for two seconds after startup, unless
it already runs: starting it loads every tool module, and with them
Org and its agenda, clock and capture, about a quarter of a second of
startup that no frame waits for.  The bridge does not retry: it exits
when the socket does not exist yet, so an agent started in the first
seconds after Emacs needs restarting.
Codex connects through the upstream Python bridge installed with the
package. Register it once on each host, then restart Codex:

#+BEGIN_SRC zsh :tangle no
codex mcp add emacs-tools -- \
  "$HOME/.emacs.d/straight/repos/emacs-mcp-server/mcp-wrapper.py" \
  "$HOME/.emacs.d/var/mcp-server/emacs-mcp-server.sock"
codex mcp get emacs-tools
#+END_SRC

The Nix configuration provides Python 3 for that bridge and =socat=
for clients that connect directly to the socket.

#+BEGIN_SRC elisp
(use-package mcp-server
  :straight (:type git
             :host github
             :repo "rhblind/emacs-mcp-server"
             :files ("*.el" "tools/*.el" "mcp-wrapper.py" "mcp-wrapper.sh"))
  :custom (mcp-server-socket-directory
           (no-littering-expand-var-file-name "mcp-server/"))
  :init
  ;; Not on `emacs-startup-hook': starting the server loads every tool
  ;; module, and with them Org and its agenda, clock and capture.  Idle
  ;; time counts from the end of startup, so this stays off the path to
  ;; the first frame, and runs after the Emacs server's one-second idle
  ;; timer.  A server already started, by hand or from local.el, is left
  ;; alone: starting it again signals an error.
  (run-with-idle-timer 2 nil
                       (lambda ()
                         (unless (bound-and-true-p mcp-server-running)
                           (mcp-server-start-unix)))))
#+END_SRC

* Machine-local configuration

Settings that differ between machines (identity, local tool paths)
live in a file =local.el= at the root of =user-emacs-directory=.  This file is gitignored so it never
appears in the public repository.  A documented skeleton is provided
as =local.el.example=; copy it to =local.el= and fill in your values.
[[file:docs/reference/local-el.org][local.el variables]] lists the variables a machine sets there.

=local.el= is loaded after the rest of =init.el= so its settings
override anything declared earlier.  Use =with-eval-after-load= to
defer settings that depend on a package being present (see the example
file).

#+BEGIN_SRC elisp
;; Load machine-local overrides — gitignored, never committed.
(let ((f (expand-file-name "local.el" user-emacs-directory)))
  (when (file-exists-p f)
    (load f nil :nomessage)))
#+END_SRC
