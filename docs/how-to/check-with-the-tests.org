#+TITLE: Check the configuration with its tests
#+OPTIONS: toc:nil num:nil

For a reader who wants to know that the configuration works on this
machine: after installing it, after adding programs, or after an
update.  The tests run in private Emacs sessions of their own and
never touch the Emacs you use.  They need Emacs 30 or later and
python3.

* Install every package first

Emacs installs some packages only the first time you use them, while
the tests never download anything: they read the packages already
installed.  So install them all once, and again after an update.  The
setup script does it; despite its directory, it needs no Nix:

#+BEGIN_SRC sh :beginner both
cd ~/.emacs.d
nix/setup.sh packages
#+END_SRC

* Run the quick checks

First the checks that need no Emacs session:

#+BEGIN_SRC sh :beginner both
tests/run static
#+END_SRC

Then, on Linux, where the tests draw their windows on a private
display (Xvfb):

#+BEGIN_SRC sh :beginner nixos
tests/run fast
#+END_SRC

On macOS, whose Emacs cannot draw on such a display, and on Linux
without Xvfb, run them without windows:

#+BEGIN_SRC sh :beginner macos
EMACS_TEST_GUI=0 tests/run fast
#+END_SRC

* Read the result

Each command prints one line per test file and ends with a summary;
everything should pass.  A test that needs a program you have not
installed is skipped, not failed, where the tests expect it.

When a file fails, the runner keeps its session directory and prints
its path: =messages.txt= there says what went wrong.  A missing program
is the usual cause: install it and run the command again.

[[file:../reference/tests.org][The test reference]] lists the other commands, such as the slow
=tests/run full=.
